== Препроцессор и макрокоманды

Мы уже очень бегло познакомились с ролью препроцессора в главе, посвященной компиляции (TBD). Пришла пора познакомиться с языком макросов детально, поскольку они являются весьма важной частью языка C в целом.

Прежде всего необходимо понять, что препроцессор — это отдельная программа, выполняющаяся до передачи исходного текста компилятору. Его задача — выполнить некоторые предварительные преобразования текста программы: подключить заголовочные файлы, раскрыть макроопределения, удалить комментарии и обработать директивы условной компиляции.

IMPORTANT: Препроцессор *не анализирует* синтаксис языка и *не выполняет* проверку типов. Он работает исключительно с текстом, производя в нём механические замены. Это свойство определяет основные опасности макрокоманд.

=== Директивы препроцессора

Все директивы препроцессора начинаются со знака `#`, который должен располагаться в начале строки (допустимы только пробельные символы перед ним). Директива не требует точки с запятой в конце и действует до конца строки.

Основные директивы:

[cols="^1,^3", options="header"]
|===
|Директива |Назначение

|`#define`
|Определение макроса

|`#undef`
|Отмена определения макроса

|`#include`
|Включение содержимого файла

|`#ifdef`, `#ifndef`, `#if`, `#elif`, `#else`, `#endif`
|Условная компиляция

|`#error`, `#warning`
|Выдача сообщения на этапе препроцессинга

|`#pragma`
|Передача указаний компилятору
|===

=== Объектные макросы (макросы без аргументов)

*Объектный макрос* — это именованная текстовая последовательность, которая подставляется вместо имени макроса везде, где оно встречается в исходном тексте после точки определения.

[source,c]
----
#define MAX_STUDENTS 30
#define PI 3.14159265358979

int group[MAX_STUDENTS];
double area = PI * r * r;
----

После работы препроцессора текст примет вид:

[source,c]
----
int group[30];
double area = 3.14159265358979 * r * r;
----

Объектные макросы традиционно используются для задания именованных констант. Это устраняет так называемые *магические числа* — безымянные числовые литералы, смысл которых неочевиден из контекста.

Макрос может быть определён и без тела — такое определение используется как *флаг* для *директив условной компиляции* (см. ниже):

[source,c]
----
#define DEBUG
----

Отменить определение макроса позволяет директива `#undef`:

[source,c]
----
#undef DEBUG
----

=== Функциональные макросы (макросы с аргументами)

*Функциональный макрос* принимает аргументы и подставляет их в тело определения. Синтаксически такой макрос напоминает вызов функции, однако механизм его работы принципиально иной: происходит не вычисление, а *текстовая подстановка*.

[source,c]
----
#define SQUARE(x) ((x) * (x))
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int y = SQUARE(5);       /* y = ((5) * (5)) */
int m = MAX(a + 1, b);   /* m = ((a + 1) > (b) ? (a + 1) : (b)) */
----

Обратите внимание на скобки вокруг каждого аргумента и вокруг всего тела макроса. Это не излишество, а необходимость, связанная с приоритетом операций. Рассмотрим пример без таких скобок:

[source,c]
----
#define BAD_SUM(a, b) a + b
int x = BAD_SUM(2, 3) * 4;
----

Раскрытие даст `2 + 3 * 4`, то есть `14`, а не ожидаемые `20`. Правильное определение:

[source,c]
----
#define GOOD_SUM(a, b) ((a) + (b))
----

=== Операторы `\#` и `##`

В теле функционального макроса могут использоваться два специальных оператора.

==== Оператор `#` (стрингификация )

Оператор `#`, стоящий перед параметром макроса, превращает фактический аргумент в строковый литерал.

[source,c]
----
#define PRINT_VAR(var, fmt) \
    printf(#var " = %" #fmt "\n", var)

int count = 42;
PRINT_VAR(count, d);
/* Раскрывается в:
   printf("count" " = %" "d" "\n", count);
   что эквивалентно:
   printf("count = %d\n", count);
*/
----

==== Оператор `##` (конкатенация)

Оператор `##` склеивает два лексических элемента в единый идентификатор.

[source,c]
----
#define MAKE_FUNC(name) void func_##name(void)

MAKE_FUNC(init);   /* Раскрывается в: void func_init(void) */
MAKE_FUNC(cleanup); /* Раскрывается в: void func_cleanup(void) */
----

Эти операторы позволяют писать макросы, генерирующие имена идентификаторов и строк, что невозможно реализовать средствами самого языка C.

=== Предопределённые макросы

Компилятор предоставляет ряд макросов, значения которых определяются автоматически. Наиболее употребительные из них:

[cols="^1,^3", options="header"]
|===
|Макрос |Значение

|`\___LINE___`
|Номер текущей строки исходного файла

|`\___FILE___`
|Имя текущего исходного файла (строковый литерал)

|`\___DATE___`
|Дата компиляции в формате "Mmm dd yyyy"

|`\___TIME___`
|Время компиляции в формате "hh:mm:ss"

|`\___STDC___`
|Определён, если компилятор соответствует стандарту \(C)

|`\___STDC_VERSION___`
|Номер версии стандарта C (например, `201112L` для C11)
|===

Эти макросы широко применяются в отладочных сообщениях:

[source,c]
----
#define LOG_ERROR(msg) \
    fprintf(stderr, "Ошибка в %s:%d — %s\n", __FILE__, __LINE__, msg)
----

=== Условная компиляция

Директивы условной компиляции позволяют включать или исключать фрагменты текста программы в зависимости от выполнения некоторых условий. Это необходимо, в частности, для:

* адаптации программы к различным операционным системам и архитектурам;
* включения отладочных фрагментов только в специальных сборках;
* предотвращения повторного включения заголовочных файлов.

==== Директивы `#ifdef` и `#ifndef`

[source,c]
----
#ifdef DEBUG
    printf("Отладочное сообщение\n");
#endif

#ifndef MAX_BUFFER
    #define MAX_BUFFER 1024
#endif
----

Директива `#ifdef NAME` эквивалентна `#if defined(NAME)`, а `#ifndef NAME` — `#if !defined(NAME)`. Оператор `defined` особенно удобен в сложных условиях:

[source,c]
----
#if defined(OS_LINUX) && !defined(DISABLE_NETWORKING)
    /* код для Linux с поддержкой сети */
#elif defined(OS_WINDOWS)
    /* код для Windows */
#else
    #error "Неподдерживаемая операционная система"
#endif
----

==== Директива `#if`

Директива `#if` позволяет включать или исключать блоки кода из компиляции в зависимости от значения константного выражения.

Сначала директива `#if` вычисляет целочисленное константное выражение, составленное из литералов и макросов. 
Если указанное выражение после `#if` вычисляется как ненулевое (то есть истинно), то весь код, который находится между `#if` и соответствующей закрывающей директивой `#endif`, включается в итоговый исходный файл для компилятора. Если же выражение равно нулю (ложно), то этот блок кода полностью игнорируется и в компиляцию не попадает. 

Синтаксис:

[source,c]
----
#if выражение
    // код для компиляции, если выражение истинно
#endif
----

IMPORTANT: Условие должно быть константным выражением (то есть его значение вычисляется на этапе компиляции). 

IMPORTANT: Директива `#if` всегда парная. Для каждой такой директивы должна быть соответствующая закрывающая `#endif`. Если этого не сделать, компилятор выдаст ошибку. 

Внутри блока #if можно использовать директивы #elif (аналог else if), #else (альтернативный блок для случая, когда #if ложен) и вложенные #if. При этом #else, если он есть, должен быть последней директивой перед #endif.

== 7.7. Защита от повторного включения

Заголовочные файлы часто включаются в программу многократно через различные цепочки `#include`. Чтобы избежать повторного определения типов, переменных и макросов, применяется *include guard*:

[source,c]
----
#ifndef MYHEADER_H
#define MYHEADER_H

/* содержимое заголовочного файла */

#endif /* MYHEADER_H */
----

Альтернативой является нестандартная, но широко поддерживаемая директива:

[source,c]
----
#pragma once
----

== 7.8. Многострочные макросы

Длинное определение макроса можно разбить на несколько строк, экранируя перевод строки обратным слешем:

[source,c]
----
#define INIT_STRUCT(s) do { \
    (s).x = 0;              \
    (s).y = 0;              \
    (s).flags = 0;          \
} while (0)
----

Обратите внимание на конструкцию `do { ... } while (0)`. Она необходима, чтобы макрос, раскрывающийся в несколько операторов, синтаксически вёл себя как *единый оператор*. Это позволяет безопасно использовать его в конструкциях `if`-`else`:

[source,c]
----
if (condition)
    INIT_STRUCT(obj);   /* без do-while здесь возникла бы ошибка */
else
    /* ... */
----

Компилятор распознаёт, что цикл выполняется ровно один раз, и оптимизирует его, не генерируя лишнего машинного кода.

== 7.9. Достоинства и недостатки макросов

Макрокоманды — мощный, но специфический механизм. Их применение должно быть осознанным.

=== Достоинства

. *Отсутствие накладных расходов.* Макрос раскрывается на этапе препроцессинга, поэтому вызов макроса не связан с передачей управления, формированием стекового кадра и возвратом из функции. Это важно в ресурсоограниченных системах.

. *Работа с синтаксисом языка.* Макросы способны генерировать идентификаторы (через `##`), преобразовывать их в строки (через `#`) и использовать информацию о месте вызова (`__FILE__`, `__LINE__`). Ни одна языковая конструкция \(C) на это не способна.

. *Условная компиляция.* Только препроцессор позволяет включать и исключать фрагменты программы в зависимости от конфигурации сборки.

. *Генерация шаблонного кода.* С помощью макросов можно создавать семейства однотипных функций и структур, что востребовано в системном программировании.

=== Недостатки

. *Отсутствие проверки типов.* Препроцессор не различает типы данных. Ошибка, связанная с несовместимостью аргументов, проявится лишь на этапе компиляции раскрытого текста, что затрудняет локализацию проблемы.

. *Многократное вычисление аргументов.* Если аргумент макроса используется в теле несколько раз, он вычисляется соответствующее число раз. Вызов `SQUARE(x++)` приведёт к двойному инкременту переменной `x`, что является источником трудноуловимых ошибок.

. *Сложность отладки.* Отладчик работает с раскрытым текстом, а не с исходным макросом. Сообщения об ошибках указывают на строки раскрытия, а не на строки вызова.

. *Нарушение области видимости.* Макрос действует глобально от точки определения до конца файла или до директивы `#undef`. Он не подчиняется правилам блочной области видимости языка \(C).

. *Конфликты имён.* Имя макроса может случайно совпасть с именем переменной, функции или поля структуры, что приведёт к непредсказуемым подстановкам.

== 7.10. Когда применять макросы, а когда — отказаться от них

Общее правило: *если задачу можно решить средствами самого языка \(C), макрос использовать не следует*.

=== Когда макросы оправданы

* *Условная компиляция* — для адаптации программы к различным платформам и конфигурациям сборки. Альтернатив здесь нет.
* *Защита заголовочных файлов* от повторного включения.
* *Отладочные и логгирующие макросы*, использующие `__FILE__` и `__LINE__`.
* *Генерация однотипного кода* — например, семейство функций для разных типов данных, когда обобщённые средства языка недостаточны.
* *Короткие выражения*, где важна каждая операция (в критичных по производительности участках встраиваемых систем).

=== Когда следует отказаться от макросов

[cols="^1,^1,^1", options="header"]
|===
|Задача |Плохо (макрос) |Хорошо (средства языка \(C))

|Именованные целочисленные константы
|`#define SIZE 100`
|`enum { SIZE = 100 };`

|Простые функции
|`#define SQUARE(x) ((x)*(x))`
|`static inline int square(int x) { return x * x; }`

|Полиморфные операции
|`#define MAX(a,b) ...`
|Отдельные функции `max_i`, `max_d` или `_Generic` \(C11)

|Строковые константы
|`#define MSG "text"`
|`static const char MSG[] = "text";`
|===

Конструкция `static inline` (стандарт C99) позволяет получить функцию, тело которой встраивается в место вызова, — то есть достичь того же отсутствия накладных расходов, что и у макроса, но с полной проверкой типов и корректной работой отладчика.

Оператор `_Generic` (стандарт C11) даёт возможность выбирать реализацию в зависимости от типа аргумента, что позволяет создавать типобезопасные полиморфные конструкции без текстовых подстановок.

[source,c]
----
static inline int    max_i(int a, int b)       { return a > b ? a : b; }
static inline double max_d(double a, double b) { return a > b ? a : b; }

#define MAX(a, b) _Generic((a), \
    int:    max_i,              \
    double: max_d               \
)(a, b)
----

В этом определании макрос используется лишь как тонкая оболочка над типобезопасными функциями, что существенно снижает связанные с макросами риски.

== Резюме

Макрокоманды — неотъемлемая часть языка \(C), унаследованная от его исторического развития. Они предоставляют возможности, недоступные языковым средствам: условную компиляцию, работу с именами идентификаторов, генерацию кода. Однако их слепая текстовая природа делает макросы источником труднодиагностируемых ошибок.

Современный стиль программирования на \(C) предполагает *минимизацию* использования макросов. Там, где раньше применялись макросы для констант и простых функций, сегодня следует использовать `enum` и `static inline`. Макросы должны оставаться там, где они действительно незаменимы: в условной компиляции, в отладочных конструкциях и в задачах генерации кода.

Привет! Прежде чем мы начнем писать код на C, нам нужно познакомиться с нашим невидимым помощником — *препроцессором*. 

Представь, что компилятор — это строгий экзаменатор, который понимает только идеальный, структурированный язык. А препроцессор — это твой ассистент, который работает *до* экзамена. Его задача — подготовить текст программы: убрать мусор, расставить нужные вставки и заменить сокращения на полные формулировки. 

Препроцессор *не понимает* логику программы (циклы, условия, типы данных). Для него программа — это просто большой текстовый файл. Его главный инструмент — *директивы* (команды, начинающиеся со знака `#`) и *макрокоманды* (или просто *макросы*).

== 1. Что такое макрос?

Самая известная директива препроцессора — это `#define`. С её помощью мы создаем макросы. По сути, макрос — это *продвинутая текстовая замена* (как функция «Найти и заменить» в текстовом редакторе).

Когда препроцессор видит в коде имя макроса, он просто стирает его и вписывает вместо него то, что мы указали в `#define`. Этот процесс называется *раскрытием макроса*.

Макросы делятся на два основных типа:

=== А. Объектные макросы (константы)
Используются для замены простых значений. Это избавляет нас от «магических чисел» в коде.

[source,c]
----
#define MAX_STUDENTS 30
#define PI 3.14159

// Как это видит компилятор после работы препроцессора:
// int group[MAX_STUDENTS];  -->  int group[30];
// double area = PI * r * r; -->  double area = 3.14159 * r * r;
----

=== Б. Функциеподобные макросы
Выглядят как функции, принимают аргументы, но работают как текстовая подстановка.

[source,c]
----
#define SQUARE(x) ((x) * (x))

int a = SQUARE(5); // Препроцессор заменит на: int a = ((5) * (5));
----

== 2. Специальные операторы в макросах

Препроцессор умеет делать трюки, недоступные обычному коду. Вот два самых полезных:

. *Оператор `#` (Стротификация / Превращение в строку)* +
Превращает аргумент макроса в строковый литерал (оборачивает в кавычки).
+
[source,c]
----
#define PRINT_VAR(x) printf("Значение " #x " = %d\n", x)

int age = 20;
PRINT_VAR(age); 
// Раскроется в: printf("Значение " "age" " = %d\n", age);
// Выведет на экран: Значение age = 20
----

. *Оператор `##` (Склеивание / Конкатенация)* +
Склеивает два аргумента в одно целое. Часто используется для генерации имен переменных.
+
[source,c]
----
#define MAKE_VAR(type, name) type var_##name

MAKE_VAR(int, count); // Раскроется в: int var_count;
----

== 3. Плюсы и минусы макросов

Макросы — это мощное, но опасное оружие. В системном программировании и в ядре Linux они незаменимы, но использовать их нужно с осторожностью. Давайте разберем, почему.

=== ✅ Плюсы макросов

. *Отсутствие накладных расходов.* +
Поскольку макрос — это просто вставка текста, нет затрат времени на вызов функции (передачу аргументов, создание стека, возврат). _Примечание: начиная с C99, ключевое слово `inline` позволяет обычным функциям вести себя похожим образом, но макросы всё равно остаются быстрее в некоторых случаях._

. *Метапрограммирование и генерация кода.* +
Макросы могут писать код за вас. С их помощью можно создавать сложные конструкции, которые невозможно написать обычными средствами языка (например, макросы для логгирования, отладки или создания таблиц функций).

. *Условная компиляция.* +
С помощью `#ifdef` / `#ifndef` можно включать или исключать куски кода в зависимости от условий (например, собирать разный код для Windows и Linux, или включать отладочную печать только в тестовой сборке).

. *Работа с исходным кодом.* +
Благодаря операторам `#` и `##` макросы могут "видеть" имена переменных и генерировать уникальные идентификаторы (например, `__LINE__` или `__FILE__`).

=== ❌ Минусы макросов (и почему их не любят)

. *Нет проверки типов!* +
Препроцессор слеп. Он не знает, что такое `int` или `double`.
+
[source,c]
----
#define MAX(a, b) ((a) > (b) ? (a) : (b))
// Мы можем случайно сравнить число с указателем или строкой, 
// и компилятор выдаст ошибку уже на этапе раскрытия, где её трудно найти.
----

. *Опасность побочных эффектов (Классическая ловушка!).* +
Посмотрите на этот макрос: `#define SQUARE(x) ((x) * (x))`. +
Что будет, если вызвать `SQUARE(a++)`? +
Препроцессор раскроет это в: `((a++) * (a++))`. +
Переменная `a` *инкрементируется дважды*! Это классическая ошибка, которая ломает логику программы.

. *Проблема приоритета операций.* +
[source,c]
----
#define SUM(a, b) a + b
int x = SUM(2, 3) * 4; 
// Раскроется в: int x = 2 + 3 * 4; (результат 14, а не 20!)
----
*Решение:* Всегда брать аргументы и всё тело макроса в дополнительные скобки: `#define SUM(a, b) ((a) + (b))`.

. *Кошмар при отладке.* +
Если внутри макроса ошибка, компилятор укажет на строку, где макрос *раскрылся*, а не там, где вы его *вызвали*. В сложных макросах из десятков строк найти ошибку бывает невероятно сложно.

. *Игнорирование областей видимости.* +
Макросы не знают про фигурные скобки `{}`. Если вы определили макрос в одном файле, он будет действовать во всех файлах, подключенных после него, пока не встретится `#undef`.

== 4. Золотые правила написания макросов (Survival Guide)

Если вам приходится писать макрос (например, в лабораторной или на курсе архитектуры ЭВМ), запомните эти правила, чтобы не "выстрелить себе в ногу":

*Правило 1: Всегда заключайте аргументы в скобки.*
[source,c]
----
// Плохо:
#define MULT(a, b) a * b 
// Хорошо:
#define MULT(a, b) ((a) * (b))
----

*Правило 2: Используйте конструкцию `do { ... } while(0)` для многострочных макросов.* +
Это хитрый трюк, который позволяет макросу вести себя как *один* оператор, что спасает от ошибок в конструкциях `if-else`.
[source,c]
----
// Плохо (если в if не поставить скобки, else сломается):
#define SWAP(a, b) int temp = a; a = b; b = temp;

// Хорошо:
#define SWAP(a, b) do { \
    int temp = a; \
    a = b; \
    b = temp; \
} while(0)
----
*Почему `while(0)`?* Компилятор оптимизирует этот цикл и выполнит код ровно один раз, но синтаксически для компилятора это выглядит как один цельный блок с точкой с запятой в конце.

== 5. Чем заменять макросы в современном C?

Использование макросов считается дурным тоном, *если задачу можно решить стандартными средствами языка*. В современном C (начиная с C99 и C11) есть мощные альтернативы, которые делают макросы менее нужными.

[cols="^1,^1,^1", options="header"]
|===
|Задача |Плохо (Макрос) |Хорошо (Современный C)

|Именованные константы
|`#define MAX_SIZE 100`
|`enum { MAX_SIZE = 100 };` или `const int MAX_SIZE = 100;`

|Простые функции (swap, abs, square)
|`#define SWAP(a,b) ...`
|`static inline` функции (появились в C99)

|Полиморфные функции (MAX для разных типов)
|`#define MAX(a,b) ...`
|Отдельные функции: `max_i`, `max_d`, `max_l` ИЛИ `_Generic` (C11)

|Строковые константы
|`#define MSG "Hello"`
|`static const char MSG[] = "Hello";`
|===

Разберём ключевые инструменты C подробнее:

=== `static inline` — главный друг программиста на C

Начиная со стандарта C99, в языке появились `inline`-функции. Ключевое слово `static` делает функцию локальной для текущего файла (чтобы линковщик не ругался на дубликаты).

[source,c]
----
// Вместо макроса:
// #define SQUARE(x) ((x) * (x))

// Пишем типобезопасную inline-функцию:
static inline int square_int(int x) {
    return x * x;
}

static inline double square_double(double x) {
    return x * x;
}
----

Компилятор встроит тело такой функции прямо в место вызова — *никаких накладных расходов*, как с макросом, но с полной проверкой типов!

=== `enum` для целочисленных констант

В C `const int` не всегда является *константой времени компиляции*. Например, нельзя написать `int arr[SIZE];`, если `SIZE` — это `const int` (в отличие от переменных, инициализированных через `enum`). Поэтому для целочисленных констант часто используют анонимные `enum`:

[source,c]
----
enum {
    MAX_STUDENTS = 30,
    MAX_GROUPS   = 5
};

int group[MAX_STUDENTS]; // Работает! MAX_STUDENTS — настоящая константа.
----

=== `_Generic` из C11 — «шаблоны» для C

Если вам нужна полиморфная функция (как `MAX` для разных типов), в C11 появился оператор `_Generic`, который позволяет выбрать нужную функцию в зависимости от типа аргумента:

[source,c]
----
static inline int    max_i(int a, int b)       { return a > b ? a : b; }
static inline double max_d(double a, double b) { return a > b ? a : b; }

#define MAX(a, b) _Generic((a), \
    int:    max_i,              \
    double: max_d               \
)(a, b)
----

Теперь `MAX` — это уже не слепая текстовая подстановка, а типобезопасная конструкция. Полностью отказаться от макросов в C невозможно (особенно для условной компиляции и отладки), но для констант и простых функций стоит использовать `enum` и `static inline`.

=== Итог раздела

* Препроцессор — это мощный инструмент для управления текстом программы до её компиляции.
* Макросы позволяют писать компактный и гибкий код, но требуют предельной осторожности.
* В современном C (C99, C11) для констант и функций есть типобезопасные альтернативы: `enum`, `static inline`, `_Generic`.
* Запомните главное: *препроцессор не думает, он просто заменяет текст*. Вся ответственность за безопасность этого текста лежит на вас!
