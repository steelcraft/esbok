== Скалярные типы

**Скалярным** называется тип, объекты которого содержат ровно одно значение, в отличие от **агрегатных** типов (массивов и структур), объекты которых содержат множество значений, организованных определённым образом.

Скалярные типы включают в себя *арифметические* типы и типы-*указатели*. Арифметические типы, в свою очередь,
подразделяются на *целочисленные* и *вещественные*.

То, что скаляр содержит одно значение, определяет характер операций над ним: присваивание копирует значение целиком, сравнение сопоставляет два значения, передача в функцию передаёт одно значение.

=== Целочисленные типы (`int`)

К целочисленным типам относятся:

* *символьные типы*: `char`, `signed char`, `unsigned char`;
* *целые со знаком*: `signed char`, `short`, `int`, `long`, `long long`;
* *целые без знака*: `unsigned char`, `unsigned short`, `unsigned int`,   `unsigned long`, `unsigned long long`;
* *булев тип*: `bool` (в C99/C11/C17 — `_Bool`);
* *перечисления*: `enum`;
* *произвольные целые*: `_BitInt(N)` и `unsigned _BitInt(N)` (с C23).

Тип `char` может быть как знаковым, так и беззнаковым; это определяет конкретная реализация.

Типы `char`, `signed char` и `unsigned char` совместно называются *символьными типами* (character types).

NOTE: `char`, `signed char` и `unsigned char` -- это три *разных* типа!

==== Домен

Ранее (TBD) упоминалось, что в языке C не специфицируется точный размер определенного типа в байтах. Вместо этого стандарт гарантирует лишь **минимальный** домен значений для каждого типа:

[cols="1,2,2",options="header"]
|===
| Тип | Минимальный знаковый домен | Беззнаковый аналог

| `char` | −127 … 127 *или* 0 … 255 | знак зависит от реализации
| `signed char` | −127 … 127 | `unsigned char`: 0 … 255
| `short` | −32 767 … 32 767 | 0 … 65 535
| `int` | −32 767 … 32 767 | 0 … 65 535
| `long` | −2 147 483 647 … 2 147 483 647 | 0 … 4 294 967 295
| `long long` | −2^63^ + 1 … 2^63^ − 1 | 0 … 2^64^ − 1
|===

На многих платформах домены шире минимума. Ниже приведены домены для некоторых распространенных *моделей данных*:

[cols="2,4,2,2,2,2,3,2",options="header"]
|===
| Модель | Применение | `char` | `short` | `int` | `long` | `long long` | `void*`

| LP32 | Win16 API | 8 | 16 | 16 | 32 | 64 | 4
| ILP32 |  Win32 API, Unix, Linux, macOS | 8 | 16 | 32 | 32 | 64 | 4
| LLP64 |  ARM (AArch64),  Windows API (x64) | 8 | 16 | 32 | 32 | 64 | 8
| LP64 |  Unix, Linux, macOS (64 bit) | 8 | 16 | 32 | 64 | 64 | 8
|===

Для случаев, когда программисту требуется *точно* знать размер объекта в байтах, в заголовке `<stdint.h>` определены типы `int8_t`, `int16_t`, `int32_t`, `int64_t` и их беззнаковые аналоги, а также семейства `int_leastN_t` и `int_fastN_t` (TBD).

==== Операции

Над целочисленными типами определены следующие операции.

===== Унарные операции

* `+` -- унарный плюс (не влияет на значение операнда);
* `-` -- унарный минус (меняет знак операнда на противоположный).

===== Арифметические операции

* `+` -- сложение;
* `-` -- вычитание;
* `*` -- умножение;
* `/` -- целочисленное деление (дробная часть отбрасывается);
* `%` -- остаток от деления (взятие по модулю)

===== Побитовые операции

* `&` -- поразрядное "И";
* `|` -- поразрядное "ИЛИ";
* `^` -- поразрядное "Исключающее ИЛИ";
* `~` -- поразрядное дополнение (инверсия);
* `<<` -- сдвиг влево;
* `>>` -- сдвиг вправо.

===== Операции сравнения

* `<` -- меньше;
* `<=` -- меньше или равно;
* `>` -- больше;
* `>=` -- больше или равно;
* `==` -- равно;
* `!=` -- не равно.

===== Инкремент и декремент

* `++` -- инкремент (увеличение на единицу);
* `--` -- декремент (уменьшение на единицу.

===== Логические операции

* `&&` -- логическое "И";
* `||` -- логическое "ИЛИ";
* `!` -- отрицание.

===== Присваивание

* `=` -- объекту, находящемуся слева от оператора присваивания, присваивается значение выражения, находящегося справа.

[IMPORTANT]
====
Существует также другая форма оператора присваивания: `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=`.

Если представить его в общем виде как `?=`, где символ `?` заменяет любой из вышеперечисленных опереторов, то запись

[source,c]
----
X ?= Y;
----

почти эквивалентна

[source,c]
----
X = X ? Y;
----

за исключением того, что `X` вычисляется только один разfootnote:[Это различие существенно, если при вычислении значения `X` возникают побочные эффекты.].
====

==== Особенности поведения

===== Переполнение

При выполнении операций над целочисленными типами возможен выход за границы домена (переполнение). Поведение при переполнении принципиально различается для знаковых
и беззнаковых типов:

[source,c]
----
unsigned int u = UINT_MAX;
u + 1;          /* 0: арифметика по модулю 2^N */

int i = INT_MAX;
i + 1;          /* неопределённое поведение */
----

исходить из того, что оно не происходит (что используется для оптимизаций).
Для беззнаковых типов арифметика *всегда* выполняется по модулю 2^N^ *по определению. Для знаковых типов переполнение является *неопределённым поведением*, и компилятор не пытается отследить эту ситуацию.

===== Деление и остаток

Оператор `/` для целых *не округляет*, а просто *отбрасывает* дробную часть в сторону нуля:

[source,c]
----
 7 /  2;    /*  3 */
-7 /  2;    /* -3 */
 7 / -2;    /* -3 */
-7 / -2;    /*  3 */
----

Оператор `%` возвращает остаток такой, что `(a / b) * b + a % b == a`.

Деление на ноль и взятие остатка от деления на ноль приводят к неопределённому поведению.

===== Сдвиги

* Сдвиг на отрицательную величину или на величину, не меньшую ширины типа, приводит к неопределённому поведению.
* Сдвиг отрицательного знакового числа влево приводит к неопределённому поведению в C11/C17, определено в C23 при условии, что результат представим. (TBD)
* Сдвиг вправо знаковых отрицательных чисел вызывает поведение, определенное реализацией (обычно арифметический сдвиг с сохранением знака).


==== Продвижение целых

Перед выполнением большинства операций над целочисленными типами выполняется **продвижение целых** (integer promotions).

Если тип операнда имеет меньшую разрядность, чем `int`, он преобразуется к `int` (если `int` может представить все значения исходного типа) либо к `unsigned int` (в противном случае).

К операндам, к которым применяется продвижение, относятся:

* операнды унарных операторов `+`, `-`, `~`;
* операнды `char` и `short` (любого знака) в бинарных операторах;
* операнды битовых полей, если их тип имеет меньшую разрядность, чем `int`;
* условие оператора `?:`.

Примеры:

[source,c]
----
unsigned char a = 255;
unsigned char b = 1;

a + b;        /* 256, а не 0 */
----

Операнды `a` и `b` продвигаются до `int`, поэтому сложение выполняется в домене `int` и дает в результате значение 256. Приведение обратно к `unsigned char` не происходит.

[source,c]
----
unsigned char c = 0xFF;
~c;           /* не 0x00, а 0xFFFFFF00 (на 32-битном int) */
----

Оператор `~` применяется уже после продвижения, поэтому инвертируются все 32 бита.

[source,c]
----
unsigned char x = 0;
-x;           /* тип результата — int, значение 0 */
----

Унарный минус возвращает `int`, а не `unsigned char`.

WARNING: Продвижение целых — одна из наиболее частых причин «неожиданного» поведения в программах на C. Внимательно разберитесь в этом.

=== Вещественные типы

К вещественным типам относятся:

* `float` — 32-битный двоичный формат (IEC 60559 binary32);
* `double` — 64-битный двоичный формат (IEC 60559 binary64);
* `long double` — расширенный формат, зависящий от реализации
  (80-битный на x86, binary128 на ARM, иногда совпадает с `double`);
* с C23 в основном тексте — децимальные типы `_Decimal32`,
  `_Decimal64`, `_Decimal128`.

==== Домен
  
Домен включаеn:

* нормализованные конечные числа;
* субнормальные (денормализованные) числа;
* два нуля: `+0` и `−0`;
* две бесконечности: `+∞` и `−∞`;
* множество NaN (quiet и signaling).

IMPORTANT: Важно помнить, что **домен вещественного типа включает не все вещественные числа**, а конечное множество представимых чисел вместе со специальными значениями (±0, ±∞, NaN). Это естественное следствие огранниченного числа разрядов для представления таких чисел. Децимальные типы обладают иным доменом: в них точно представимы десятичные дроби вида `0.1`, что делает их пригодными для финансовых вычислений.

[source,c]
----
0.1 + 0.2 == 0.3;       /* false: 0.1 и 0.2 не представимы точно */
NAN == NAN;             /* false: NaN не равен ничему */
+0.0 == -0.0;           /* true: нули равны при сравнении */
1.0 / 0.0;              /* +inf, а не аварийное завершение */
----

==== Особенности поведения

При применении побитовых операций (как и арифметических) значение операндов продвигается до `int`, что приводит к неочевидным на первый взгляд последствиям:

[source,c]
----
true + true;    /* 2, тип int */
~false;         /* -1 (все биты инвертированы в promoted int) */
----

Любое скалярное значение при приведении к `bool` принимает значение 0 или 1:

[source,c]
----
bool a = 42;        /* true  */
bool b = 0.0;       /* false */
bool c = NULL;      /* false */
----

==== Эволюция

* В ранних версиях языка в качестве логических значений использовались целочисленные (`int`).
* В C99 введён тип `_Bool`; идентификаторы `bool`, `true`, `false` определены как макросы в заголовке `<stdbool.h>`.
* В C23 `bool`, `true`, `false` стали ключевыми словами. Заголовок `<stdbool.h>` сохранён для совместимости с предыдущими версиями.


=== Указатели

*Указатель* -- это производный тип, значение которого обеспечивает *доступ* к объекту (или функции) некоторого другого типа. Стандарт языка C намеренно избегает определения указателя как "адреса": на большинстве современных архитектур с плоской моделью памяти значение указателя действительно хранится как адрес ячейки, но в общем случае это может быть пара "сегмент:смещение", capability с метаданными, индекс в таблице дескрипторов или нечто иное. Поэтому корректнее говорить, что указатель *указывает* (points to) на объект, а не "равен его адресу".

Объявление указателя имеет вид `T *p`, где `T` -- тип объекта, на который он указывает.

==== Операции над указателями

* *присваивание* `p = q`. Указатель может быть присвоен:
** указателю того же типа;
** указателю типа `void *` и обратно -- неявно, без приведения (именно поэтому `void *` используется как "указатель общего назначения");
** указателю на совместимый тип (обычно с предупреждением компилятора);
** специальному значению *нулевого указателя* -- константе `NULL` (макрос из `<stddef.h>`) или целочисленной константе `0`. Начиная со стандарта C23 введено ключевое слово `nullptr` (см. раздел, посвящённый C23).

* *разыменование* `*p` -- получение объекта, на который указывает `p`;

* *доступ к полю структуры* `p->member` (эквивалентно `(*p).member`);

* *арифметика*:
** `p + n`, `p - n` -- смещение на `n` _элементов_, то есть на `n * sizeof(T)` байт;
** `p - q` -- расстояние в элементах между двумя указателями (определено только если оба указателя ссылаются на элементы одного массива или на элемент сразу за его концом);

* *сравнение*:
** `p == q`, `p != q` -- проверка, указывают ли два указателя на один и тот же объект (или оба являются нулевыми);
** `p < q`, `p > q`, `p <= q`, `p >= q` -- сравнение порядка определено стандартом *только* для указателей на элементы одного массива (или на элемент сразу за его концом) и для указателей на поля одной `struct` (в порядке объявления полей). В остальных случаях результат не определён.
** сравнение с нулевым указателем (`p == NULL`) -- корректно всегда и используется для проверки валидности указателя.

[source,c]
----
int a[10];
int *p = a;       /* присваивание: указатель на массив -> указатель на int */
int *q = p;       /* присваивание указателей одного типа */
void *v = p;      /* неявное преобразование в void * */

p + 1;            /* смещение на sizeof(int) байт */
p == q;           /* истинно: оба указывают на a[0] */
p < &a[5];        /* истинно: оба внутри одного массива */
p == NULL;        /* ложно: p не является нулевым указателем */
----

Именно тип `T` определяет, каков размер одного шага указательной арифметики. Для указателя типа `double *` тот же оператор `+ 1` приведёт к иному смещению, чем для `int *`.

Особый случай представляет тип `void *`: указатель на объект неизвестного типа. В языке C он неявно преобразуется в указатель на любой объектный тип и обратно, однако арифметика над ним стандартом не определена (некоторые компиляторы, например GCC, допускают её как расширение, считая размер элемента равным 1).

До стандарта C23 нулевой указатель записывался как `NULL` (макрос из стандартного заголовочного файла) либо как целочисленная константа `0`. В C23 введено ключевое слово `nullptr` (см. раздел, посвящённый C23).









== Обычные арифметические преобразования

Когда в бинарной операции участвуют два операнда разных целочисленных
или вещественных типов, сначала к обоим применяются продвижения целых,
а затем — **обычные арифметические преобразования** (usual arithmetic
conversions), приводящие операнды к общему типу.

Правила (упрощённо):

. Если один операнд имеет тип `long double`, другой приводится к `long double`.
. Иначе если один — `double`, другой — к `double`.
. Иначе если один — `float`, другой — к `float`.
. Иначе применяются продвижения целых.
. Если после продвижения типы совпадают — операция выполняется в этом типе.
. Иначе если оба операнда одного знака — операнд меньшего ранга
  приводится к типу операнда большего ранга.
. Иначе (операнды разных знаков):
  ** если беззнаковый тип имеет ранг не ниже знакового — знаковый
     приводится к беззнаковому;
  ** если знаковый тип может представить все значения беззнакового —
     беззнаковый приводится к знаковому;
  ** иначе оба приводятся к беззнаковому типу, соответствующему
     знаковому.

=== Практические следствия

[source,c]
----
int    i = -1;
unsigned u = 1;

i < u;      /* false: i приводится к unsigned, становится UINT_MAX */
----

Смешение знаковых и беззнаковых типов — классический источник ошибок.
Компиляторы обычно выдают предупреждение при таком сравнении.

[source,c]
----
int    a = 1;
double b = 2.0;

a + b;      /* тип результата — double, значение 3.0 */
----

При смешении целого и вещественного типов целое приводится к вещественному.












== Указатели

=== Семантика

Указатель — скалярный тип, домен которого состоит из **адресов объектов
и функций определённого типа** плюс особое значение — нулевой указатель.
Тип указателя определяет, *какой тип* имеет объект по адресу, —
это влияет на шаг указательной арифметики и на разыменование.

[source,c]
----
int    a[10];
int   *p = a;
double *q = (double *)a;

p + 1;    /* адрес a[1], смещение на sizeof(int) */
q + 1;    /* смещение на sizeof(double) */
----

=== Домен значений

Домен указателя `T *` — это:

* адреса всех объектов типа `T`, существующих в программе;
* адреса всех функций типа `T` (для указателей на функции);
* адреса элементов массива `T` и позиции «за последним элементом»;
* нулевой указатель.

Разные типы указателей — разные типы, даже если они занимают одинаковое
число байт. Указатель `int *` и указатель `double *` несовместимы.

=== Множество операций

* разыменование: `*p`;
* доступ к полю структуры: `p->member`;
* арифметика: `p + n`, `p - n`, `p - q` (внутри одного массива);
* сравнения: `==`, `!=`, `<`, `<=`, `>`, `>=` (для указателей
  внутри одного массива или на один объект);
* присваивание;
* приведение к другим типам указателей (явное);
* приведение к целым типам достаточной ширины (`intptr_t`, `uintptr_t`
  из `<stdint.h>`).

Оператор `sizeof` к указателю возвращает размер самого указателя,
а не объекта, на который он ссылается.

=== Особый случай: `void *`

Тип `void *` — указатель на объект неизвестного типа. В C он неявно
преобразуется в любой объектный указатель и обратно. Арифметика над
`void *` стандартом не определена (некоторые реализации допускают её
как расширение, трактуя `sizeof(void)` как 1).

=== Нулевой указатель в C23

До C23 нулевой указатель записывался через макрос `NULL` или целочисленную
константу `0`. В C23 введено ключевое слово `nullptr` с собственным
типом `nullptr_t`, домен которого состоит из единственного значения —
нулевого указателя.

[source,c]
----
int *p = nullptr;

void f(int *);
f(nullptr);     /* однозначно: указатель, а не целое */
----


== Перечисления

=== Семантика

Перечисление (`enum`) — целочисленный тип, значения которого
идентифицируются именами-перечислителями.

[source,c]
----
enum Color { RED, GREEN, BLUE };
enum Color c = RED;
----

=== Домен значений

В отличие от C++, перечисление в C **не образует замкнутого множества**.
Переменная перечислимого типа совместима с некоторым целочисленным типом
(выбираемым реализацией), и стандарт не гарантирует, что она никогда
не примет значение вне списка перечислителей.

[source,c]
----
enum Color c = RED;
c = 42;         /* допустимо в C, неопределённое поведение в C++ */
----

=== Множество операций

Над перечислениями определены те же операции, что и над целыми:
арифметика, сравнения, присваивания. При выполнении операций
перечисления продвигаются до целого типа.


== Произвольные целые в C23: `_BitInt(N)`

Стандарт C23 ввёл **genuinely новый** скалярный тип — `_BitInt(N)`,
целое число ровно из N бит.

[source,c]
----
_BitInt(12)          small  = 123wb;
unsigned _BitInt(40) medium = 1000000000000ub;
_BitInt(73)          large  = 0wb;
----

=== Домен значений

* знаковый `_BitInt(N)`: от −2^(N−1)^ до 2^(N−1)^ − 1;
* беззнаковый `unsigned _BitInt(N)`: от 0 до 2^N^ − 1.

Параметр N может быть любым от 1 до значения, публикуемого реализацией
в макросе `BITINT_MAXWIDTH` заголовка `<limits.h>` (стандарт требует
поддержки минимум 1…65535).

=== Множество операций

Те же, что и для обычных целых: арифметика, побитовые операции, сравнения.
Отличия:

* ширина типа точно равна N бит, а не «не менее N бит»;
* суффиксы литералов: `wb` / `WB` для знаковых, `ub` / `UB` для беззнаковых;
* продвижение целых для `_BitInt(N)` при N ≤ ширины `int` выполняется
  до `int`, иначе — до `_BitInt(N)` (беззнаковый — до `unsigned _BitInt(N)`).

=== Область применения

* криптография и хеш-функции, где нужны нестандартные ширины (256, 521 бит);
* сетевые протоколы с полями произвольной ширины;
* работа с аппаратными регистрами;
* ситуации, где требуется ширина, гарантированно не зависящая от платформы.


== Преобразования между скалярными типами

=== Неявные приведения

Неявные приведения происходят:

* при присваивании значения одного скалярного типа переменной другого;
* при передаче аргумента функции (если есть прототип);
* при возврате значения из функции;
* в бинарных операциях — через обычные арифметические преобразования;
* в условии `if`, `while`, `for`, `?:` — приведение к `bool`.

[source,c]
----
int    i = 3.7;       /* 3: отбрасывание дробной части */
double d = 42;        /* 42.0 */
bool   b = -1;        /* true */
----

=== Потеря информации

При приведении вещественного типа к целочисленному:

* дробная часть отбрасывается;
* если значение не помещается в домен целочисленного типа —
  неопределённое поведение (в C23 — определённое, но реализационно-зависимое).

При приведении целого к вещественному:

* значение округляется до ближайшего представимого;
* если значение слишком велико — поведение не определено.

При приведении между целыми不同类型的:

* беззнаковое → знаковое: битовый рисунок сохраняется, интерпретация меняется;
* знаковое → беззнаковое: отрицательные значения приводятся по модулю 2^N^;
* более широкий → более узкий: отбрасываются старшие биты.

=== Явные приведения

Оператор `(T)x` выполняет явное приведение. Он не меняет правил
преобразования, но подавляет предупреждения компилятора и делает
намерения программиста явными.

[source,c]
----
int i = (int)3.7;                 /* явно: 3 */
unsigned u = (unsigned)-1;        /* явно: UINT_MAX */
----

== Резюме

Скалярные типы языка C образуют единое семейство, объединённое тем,
что каждый объект такого типа содержит ровно одно значение.
Однако внутри этого семейства существуют существенные различия:

* **Целочисленные типы** имеют модулярную арифметику для беззнаковых
  и неопределённое поведение при переполнении для знаковых.
  Перед операциями над ними применяется продвижение целых,
  которое часто удивляет начинающих.
* **Вещественные типы** имеют конечный домен со специальными значениями,
  неассоциативную арифметику и значительную часть операций,
  вынесенную в функции `<math.h>`.
* **Булев тип** имеет минимальный домен из двух значений,
  но при арифметических операциях продвигается до `int`.
* **Указатели** имеют домен адресов, а их арифметика зависит
  от типа указуемого объекта.
* **Перечисления** в C не образуют замкнутого множества значений.
* **`_BitInt(N)`** в C23 добавляет целые произвольной ширины.
* **`nullptr`** в C23 даёт отдельный тип для нулевого указателя.

Понимание скалярных типов требует учёта трёх аспектов: домена значений,
множества операций и правил преобразований. Размер в байтах — лишь
следствие этих аспектов, а не их суть.
