== Структуры

**Структура** — это агрегатный тип, объект которого содержит **конечную упорядоченную последовательность** полей различных типов. В отличие от массива, который однороден, структура составлена из полей, каждое из которых имеет собственный тип и имя.

=== Объявление и определение

Общая форма объявления структуры:

[source,c]
----
struct tag {
    type1 field1;
    type2 field2;
    /* ... */
};
----

Объявление создаёт **новый тип**, отличный от всех других структурных типов, даже если набор полей совпадает:

[source,c]
----
struct Point {
    int x;
    int y;
};

struct Coord {
    int x;
    int y;
};

struct Point p;
struct Coord c = p;    /* ошибка: разные типы */
----

Это проявление **номинативного тождества** типов в C: тип определяется именем (тегом), а не набором полей.

NOTE: Обратите внимание на синтаксис объявления переменной структурного типа: не `Point p`, а `struct Point p`!

==== Объявление vs определение

Как и для других типов, важно различать *объявление* и *определение*:

[source,c]
----
struct Point;              /* объявление: неполный тип */
struct Point { int x, y; }; /* определение: тип полон */
----

Неполный тип структуры можно использовать только для указателей; применить `sizeof` или объявить объект нельзя до момента определения.

==== Тип и переменная в одном объявлении

Допустимо объявлять тип и переменные одновременно:

[source,c]
----
struct Point {
    int x;
    int y;
} origin, p1, p2;          /* три объекта типа struct Point */
----

Также можно объявлять структуру без тега, сразу определяя переменные:

[source,c]
----
struct {
    int x;
    int y;
} p;                        /* тип не имеет имени, повторное использование невозможно */
----

==== `typedef` для сокращения записи

Поскольку в C пространство имён тегов отделено от пространства имён идентификаторов, слово `struct` обязательно при каждом использовании:

[source,c]
----
struct Point p;             /* обязательно struct */
----

Можно ввести псевдоним типа через `typedef`:

[source,c]
----
typedef struct {
    int x;
    int y;
} Point;

Point p;                    /* struct не требуется */
----

Вариант с именованным тегом для самоссылок:

[source,c]
----
typedef struct Point Point;
struct Point {
    int x;
    int y;
};
----

=== Домен

Домен структуры — **декартово произведение** доменов её полей:

    D(struct S) = D(поле1) × D(поле2) × … × D(полеN)

[source,c]
----
struct Point {
    int x;
    int y;
};
/* D(struct Point) = D(int) × D(int) */
----

Каждое поле сохраняет собственный тип и собственный домен.

Значение структуры — это упорядоченный набор значений полей.


=== Представление в памяти: padding и выравнивание

==== Выравнивающие вставки (padding)

Стандарт допускает наличие **padding** (незаполненных байтов между полями и в конце структуры). Padding не является частью значения; он не несёт информации и **не обязан сохраняться при присваивании**.

[source,c]
----
struct Padded {
    char  a;    /* 1 байт */
    /* 3 байта padding */
    int   b;    /* 4 байта */
    char  c;    /* 1 байт */
    /* 3 байта padding */
};
/* sizeof(struct Padded) == 12 на большинстве платформ */
----

Причины padding:

* **выравнивание полей**: поле `int` на данном оборудовании требует адреса, кратного 4;
* **выравнивание всей структуры**: `sizeof(struct)` должен быть кратен её выравниванию, чтобы массивы структур работали корректно.

==== Влияние порядка полей на размер

Порядок полей **может оказывать влияние** на размер структуры:

[source,c]
----
struct A { char a; int b; char c; };   /* 12 байт */
struct B { int b; char a; char c; };   /*  8 байт */
----

Переупорядочивание полей от большего к меньшему обычно минимизирует padding.

==== Непрерывность и выравнивание

Элементы структуры располагаются в памяти **непрерывно**, но с возможными промежутками (padding). Адрес каждого поля кратен его выравниванию:

[source,c]
----
struct S {
    char  a;    /* адрес 0 */
    int   b;    /* адрес 4 (выравнивание 4) */
    short c;    /* адрес 8 (выравнивание 2) */
};
/* sizeof(struct S) == 12 (кратно максимальному выравниванию 4) */
----

WARNING: Значения padding **не определены**. Копирование структуры через `memcpy` переносит и padding, но при присваивании через оператор `=` padding может содержать произвольные значения.  Поэтому **сравнение структур через `memcmp` ненадёжно**.


=== Операции

Над структурами определены следующие операции:

[cols="1,2,3",options="header"]
|===
| Операция | Синтаксис | Комментарий

| Доступ к полю | `s.field` | через объект
| Доступ через указатель | `p->field` | эквивалентно `(*p).field`
| Присваивание целиком | `s1 = s2` | копируются все поля
| Передача по значению | `f(s)` | копия структуры
| Возврат по значению | `return s` | копия структуры
| Агрегатная инициализация | `struct S s = { ... }` | при определении
| Именованная инициализация | `struct S s = { .f = v }` | C99
| Взятие адреса | `&s`, `&s.field` | допустимо
| Сравнение адресов | `&s1 == &s2` | но не содержимого
|===

**Не определены:**

* сравнение по содержимому (`s1 == s2`);
* арифметические операции;
* побитовые операции;
* неявные приведения к другим типам.

[source,c]
----
struct Point a = { .x = 3, .y = 4 };
struct Point b = a;       /* OK: присваивание целиком */
b.x += 1;                 /* OK */
/* a == b;               */ /* ошибка: нет такой операции */
----

Сравнение структур необходимо реализовать явно, по полям:

[source,c]
----
bool point_eq(struct Point a, struct Point b) {
    return a.x == b.x && a.y == b.y;
}
----


=== Битовые поля

Битовое поле — это поле целочисленного типа с явно заданной шириной в битах. Это способ **ограничить домен** поля по ширине до N бит.

[source,c]
----
struct Flags {
    unsigned int red   : 3;   /* домен 0…7 */
    unsigned int green : 3;
    unsigned int blue  : 3;
};
----

==== Особенности битовых полей

* типом поля может быть `int`, `unsigned int`, `signed int`, `bool` (C23), или любой другой целый тип (зависит от реализации);
* нельзя взять адрес битового поля;
* битовое поле не может быть элементом массива;
* ширина поля 0 означает «выровнять следующее поле по границе единицы   размещения»;
* порядок упаковки битов в память зависит от реализации.

[source,c]
----
struct Packed {
    unsigned int a : 1;
    unsigned int b : 1;
    unsigned int   : 0;   /* выравнивание */
    unsigned int c : 4;
};
----

==== Применение

Битовые поля полезны для работы с аппаратными регистрами и упакованными форматами данных, но их использование в переносимом коде требует осторожности из-за зависимости от реализации.

=== Гибкий массив-член структуры

Начиная с C99, последним полем структуры может быть массив **без указания размера**:

[source,c]
----
struct Vector {
    size_t n;
    double v[];        /* гибкий массив */
};
----

Особенности:

* `sizeof(struct Vector)` не включает элементы гибкого массива;
* гибкий массив должен быть **последним** полем;
* структура с гибким массивом **не может** быть членом другой структуры или элементом массива;
* память под элементы выделяется отдельно, например:

[source,c]
----
struct Vector *create_vector(size_t n) {
    struct Vector *v = malloc(sizeof *v + n * sizeof(double));
    if (v) v->n = n;
    return v;
}
----

До C99 использовалось расширение GCC с синтаксисом `double v[0]`; однако стандартный способ — вовсе без указания размера: `double v[]`.


=== Ссылка на себя

Структура не может содержать саму себя по значению, поскольку в этом случае размер оказался бы неопределённым по причине рекурсии. Но она может содержать **указатель** на свой тип:

[source,c]
----
struct Node {
    int value;
    struct Node *next;       /* указатель на неполный тип — допустимо */
};
----

NOTE: Это основа для связанных списков, деревьев и других рекурсивных структур данных.

=== Инициализация

==== Агрегатная инициализация

Поля инициализируются в порядке объявления:

[source,c]
----
struct Point { int x, y; };

struct Point p1 = { 3, 4 };
struct Point p2 = { 3 };        /* p2.y = 0 */
struct Point p3 = { 0 };        /* все поля — нули */
----

Если инициализаторов меньше, чем полей, оставшиеся поля инициализируются нулями:
* для скаляров — нулевым значением,
* для указателей — нулевым указателем,
* для вложенных структур — рекурсивно.

==== Именованная инициализация (C99)

Можно явно указывать имена полей:

[source,c]
----
struct Point p = { .y = 4, .x = 3 };
----

Поля, не указанные явно, инициализируются нулями. Порядок в инициализаторе может отличаться от порядка объявления.

==== Вложенные структуры

[source,c]
----
struct Rect {
    struct Point origin;
    struct Point size;
};

struct Rect r1 = { {0, 0}, {10, 20} };
struct Rect r2 = { .origin = {0, 0}, .size = {10, 20} };
struct Rect r3 = { .origin.x = 0, .origin.y = 0,
                   .size.x = 10, .size.y = 20 };
----


== Совместимость типов структур

Две структуры совместимы, если и только если они объявлены в одной
области видимости с одним и тем же тегом и имеют одинаковый набор полей.
Две структуры с одинаковыми полями, но разными тегами — **разные типы**:

[source,c]
----
struct A { int x; };
struct B { int x; };

struct A a = {1};
struct B b = a;    /* ошибка: разные типы */
----

Это следствие номинативного тождества типов в C.


== Практические приёмы

=== Передача структур в функции

Структуры передаются по значению (копируются), что может быть
неэффективно для больших структур:

[source,c]
----
void process(struct LargeStruct s);   /* копия */
void process(const struct LargeStruct *s);  /* указатель — эффективнее */
----

Для больших структур предпочтительна передача по указателю.

=== Возврат структур из функций

Возврат структуры по значению допустим и часто оптимизируется
компилятором (NRVO — Named Return Value Optimization):

[source,c]
----
struct Point make_point(int x, int y) {
    struct Point p = { x, y };
    return p;
}
----

=== Минимизация padding

Для экономии памяти располагайте поля от большего к меньшему:

[source,c]
----
struct Compact {
    double d;    /* 8 байт */
    int    i;    /* 4 байта */
    char   c;    /* 1 байт */
    /* 3 байта padding в конце */
};
/* sizeof(struct Compact) == 16 */
----

=== Сравнение структур

Поскольку оператор `==` не определён, реализуйте сравнение явно:

[source,c]
----
bool struct_eq(struct Point a, struct Point b) {
    return a.x == b.x && a.y == b.y;
}
----

Избегайте `memcmp` из-за padding:

[source,c]
----
/* Ненадёжно: padding может содержать мусор */
/* memcmp(&a, &b, sizeof a); */
----

[cols="1,2",options="header"]
|===
| Аспект | Структура

| Домен | произведение доменов полей
| Размер | сумма размеров полей + padding
| Padding | между полями и в конце
| Битовые поля | да
| Гибкий массив | да (последнее поле)
| Самоссылка | через указатель
| Анонимные структуры (C11) | да

|===


== Резюме

Структура в языке C — это агрегатный тип, размещающий поля **параллельно**
в памяти с возможными выравнивающими вставками (padding).

* *Домен*: декартово произведение доменов полей.
* *Операции*: доступ к полям через `.` и `->`, присваивание целиком,
  передача и возврат по значению, агрегатная и именованная инициализация.
* *Не определены*: сравнение по содержимому, арифметические и побитовые
  операции.
* *Padding*: следствие выравнивания; не является частью значения.
* *Битовые поля*: позволяют сузить домен до N бит.
* *Гибкий массив* (C99): последнее поле структуры без размера.
* *Самоссылка*: через указатель на собственный тип.

Понимание структур необходимо для корректной работы с составными данными,
сериализации, взаимодействия с аппаратным обеспечением и реализации
сложных структур данных в C.
