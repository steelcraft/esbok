== Объединения

=== Определение и синтаксис

**Объединение** — это *агрегатный* тип, объект которого содержит **одно из нескольких полей** различных типов, размещённых в одной и той же области памяти. 

NOTE: В отличие от структуры, где все поля существуют *одновременно*, в объединении в каждый момент времени активно **только одно** поле.

Общая форма объявления объединения:

[source,c]
----
union tag {
    type1 field1;
    type2 field2;
    /* ... */
};
----

Объявление создаёт **новый тип**, отличный от всех других объединений и структур, даже если набор полей совпадает:

[source,c]
----
union Value {
    int i;
    double d;
};

struct ValueS {
    int i;
    double d;
};

union  Value  u;
struct ValueS s = *(struct ValueS *)&u;    /* ошибка: разные типы */
----

Это проявление **номинативного тождества** типов в C: тип определяется именем (тегом), а не набором полей. TODO: добавить ссылку.

==== Объявление vs определение

Как и для других типов, важно различать объявление и определение:

[source,c]
----
union Value;                       /* объявление: неполный тип */
union Value { int i; double d; };  /* определение: тип полон */
----

Неполный тип объединения можно использовать только для указателей; применить `sizeof` или объявить объект нельзя до момента определения.

==== Тип и переменная в одном объявлении

Допустимо объявлять тип и переменные одновременно:

[source,c]
----
union Value {
    int i;
    double d;
} v1, v2;              /* два объекта типа union Value */
----

Также можно объявлять объединение без тега:

[source,c]
----
union {
    int i;
    float f;
} u;                    /* тип не имеет имени, повторное использование невозможно */
----

==== `typedef` для сокращения записи

Можно ввести псевдоним типа через `typedef`:

[source,c]
----
typedef union {
    int i;
    double d;
} Value;

Value v;                /* union не требуется */
----

=== Домен

Домен объединения — **объединение** доменов его полей:

    D(union U) = D(поле1) ∪ D(поле2) ∪ … ∪ D(полеN)

[source,c]
----
union Value {
    int    i;
    double d;
};
/* D(union Value) = D(int) ∪ D(double) */
----

Однако, в отличие от математического объединения множеств, здесь действует важное ограничение: **в каждый момент времени активно ровно одно поле**. Объединение не может одновременно хранить значение `int` и `double`; оно хранит либо одно, либо другое.

Поле, значение которого было записано последним, называется **активным членом** объединения. Именно его значение корректно читать.

[source,c]
----
union Value u;
u.i = 42;          /* активно поле i */
u.d = 3.14;        /* теперь активно поле d, значение i утеряно */
----

Смена активного члена происходит автоматически при присваивании. Объединение «помнит» только последнее записанное поле.

=== Представление в памяти

Все поля объединения начинаются с **одного и того же адреса** в памяти:

[source,c]
----
union Value u;
(void *)&u.i == (void *)&u.d;      /* истинно: адреса совпадают */
----

Это прямое следствие того, что поля накладываются в памяти друг на друга.

==== Размер объединения

Размер объединения равен размеру **наибольшего** поля, возможно, с дополнительным padding для выравнивания:

[source,c]
----
union Value {
    char  c;       /* 1 байт */
    int   i;       /* 4 байта */
    double d;      /* 8 байт */
};
/* sizeof(union Value) == 8 (размер наибольшего поля) */
----

NOTE: Объединение экономит память: вместо суммы размеров полей (как в структуре) используется только максимум.

==== Выравнивание

Объединение выравнивается по максимальному выравниванию среди своих полей:

[source,c]
----
union U {
    char   c;      /* выравнивание 1 */
    double d;      /* выравнивание 8 */
};
/* _Alignof(union U) == 8 */
----

Это гарантирует, что любое поле объединения будет корректно выровнено при любом использовании объекта.

==== Padding

В отличие от структур, padding в объединениях появляется только **после** наибольшего поля, если это необходимо для выравнивания самого объединения:

[source,c]
----
union U {
    int   i;       /* 4 байта */
    char  c[5];    /* 5 байт */
};
/* sizeof(union U) == 8: максимум 5, но с выравниванием до 8 */
----

WARNING: Байты, не принадлежащие активному полю, имеют **неопределённое** содержимое. Чтение значения неактивного члена приводит к ошибке.


=== Операции

Над объединениями определены те же операции, что и над структурами:

[cols="1,2,3",options="header"]
|===
| Операция | Синтаксис | Комментарий

| Доступ к полю | `u.field` | через объект
| Доступ через указатель | `p->field` | эквивалентно `(*p).field`
| Присваивание целиком | `u1 = u2` | копируется представление активного поля
| Передача по значению | `f(u)` | копия объединения
| Возврат по значению | `return u` | копия объединения
| Агрегатная инициализация | `union U u = { ... }` | при определении
| Именованная инициализация | `union U u = { .f = v }` | C99
| Взятие адреса | `&u`, `&u.field` | допустимо
|===

**Не определены:**

* сравнение по содержимому (`u1 == u2`);
* арифметические операции;
* побитовые операции;
* неявные приведения к другим типам.

=== Чтение активного и неактивного члена

Правила чтения полей объединений существено отличаются от структур.

==== Чтение активного члена

Чтение активного члена всегда корректно:

[source,c]
----
union Value u = { .i = 42 };
int x = u.i;       /* OK: поле i активно */
----

==== Чтение неактивного члена

Начиная с C99 стандарт C допускает чтение члена объединения, отличного от последнего записанного. Соответствующая часть представления объекта **переинтерпретируется** как представление нового типа . Этот приём называется *type punning* (буквально "каламбур типа").

Доступ через член объединения является легальным исключением из правила строгого алиасинга (TBD).

[source,c]
----
union FloatBits {
    float    f;
    uint32_t u;
};

union FloatBits v = { .f = 3.14f };
uint32_t bits = v.u;    /* корректно: переинтерпретация представления */
----

На подобные действия, однако, однако, накладываются два ограничения.

. **Ловушечные представления.** Если переинтерпретированные биты не образуют допустимого значения целевого типа, поведение не определено:
+
[source,c]
----
union U { int i; bool b; };

union U u = { .i = 42 };
bool x = u.b;           /* UB: ловушечное представление для bool */
----
. **Неопределённые байты.** Если читаемый член по размеру больше записанного, байты за пределами записанного значения не определены:
+
[source,c]
----
union V { char c; double d; };

union V v = { .c = 'A' };
double x = v.d;         /* 7 байтов не определены */
----

WARNING: В C++ чтение неактивного члена объединения — неопределённое поведение. Потому, еси вам требуется type punning, в заголовках, общих для C и C++, используйте побитовое копирование посредством `memcpy`.

==== Общая начальная последовательность

Если объединение содержит несколько структур, и эти структуры начинаются с **одинакового набора полей** (одинаковые типы
в одном порядке), то этот начальный набор называется *общей начальной последовательностью* (common initial sequence).

В таком случае разрешено **читать общую часть** через любой член объединения, даже в том случае, если он не активен.

Требования к полям:

* Соответствующие поля должны иметь **совместимые типы**.
* В случае битовых полей он должны иметь **одинаковую ширину**.
* **Имена полей могут различаться**; это не влияет на совместимость.

Это правило действует **только в той точке программы, где компилятор видит полное определение объединения**, то есть объявление со всеми его членами. Если объединение объявлено лишь как неполный тип (`union U;` без списка членов), правило не применимо, и чтение через неактивный член становится неопределённым поведением.

Пример:

[source,c]
----
struct Point2D { int x; int y; };
struct Point3D { int x; int y; int z; };

union Geometry {
    struct Point2D p2;
    struct Point3D p3;
};

union Geometry g = { .p3 = {1, 2, 3} };

/* Здесь определение union Geometry видно — правило действует */
int cx = g.p2.x;   /* OK: 1 */
int cy = g.p2.y;   /* OK: 2 */
----

Пример, когда правило не действует:

[source,c]
----
/* В другой единице трансляции — только неполное объявление */
union Geometry;

void f(union Geometry *g) {
    /* Определение union Geometry здесь не видно.
       Правило общей начальной последовательности не применяется. */
    int x = g->p2.x;   /* UB: компилятор не знает, что p2 — член объединения */
}
----

.Гарантированно переносимая переинтерпретация
****
[source,c]
----
float f = 3.14f;
uint32_t bits;
memcpy(&bits, &f, sizeof bits);
----

Побитовое копирование при помощи `memcpy`

* не опирается на исключения алиасинга,
* работает в C++ и
* явно выражает намерение. 

Впрочем, это никак не защищает от ловушечных представлений.
****

=== Битовые поля

Битовые поля допустимы и в объединениях:

[source,c]
----
union Bits {
    unsigned int a : 3;
    unsigned int b : 5;
    unsigned int c : 8;
    unsigned int all : 16;
};
----

Особенности:

* все битовые поля накладываются на одну область памяти;
* размер объединения определяется максимальным из полей;
* порядок упаковки битов зависит от реализации;
* над битовым полем нельзя взять адрес.

Битовые поля в объединениях полезны для работы с аппаратными регистрами,
где одно и то же слово может интерпретироваться по-разному.

=== Ссылка на себя

Объединение не может содержать само себя по значению рекурсивно, но может содержать **указатель** на свой тип:

[source,c]
----
union Node {
    int         value;
    union Node *next;
};
----

=== Инициализация 

==== Агрегатная инициализация

Инициализируется всегда **первое** поле объединения:

[source,c]
----
union Value {
    int    i;
    double d;
};

union Value u1 = { 42 };          /* активно поле i */
union Value u2 = { 42.0 };        /* тоже инициализирует i (первое поле) */
----

В этом примере второй инициализатор интерпретируется как значение первого поля, даже несмотря на то, что его тип не совпадает с типом первого поля.

==== Именованная инициализация (C99)

В этом случае можно явно указать, какое поле инициализируется:

[source,c]
----
union Value u = { .d = 3.14 };    /* активно поле d */
----

Именованная инициализация более предпочтительна, так как делает намерение программиста явным.

=== Вложенные объединения

Объединения могут быть вложенными:

[source,c]
----
union Outer {
    union Inner {
        int i;
        float f;
    } inner;
    double d;
};

union Outer o = { .inner = { .f = 1.5f } };
union Outer o2 = { .d = 2.7 };
----


=== Анонимные объединения

Начиная с C11, объединения могут быть **анонимными** внутри структур или других объединений:

[source,c]
----
struct Variant {
    int type;
    union {
        int    i;
        double d;
        char   s[16];
    };
};

struct Variant v = { .type = 1, .d = 3.14 };
v.d;              /* прямой доступ */
----

Поля анонимного объединения видны напрямую, как если бы они были полями внешней структуры.

Анонимные объединения также допустимы внутри других объединений:

[source,c]
----
union Outer {
    int x;
    union {
        float f;
        double d;
    };
};

union Outer o = { .f = 1.5f };
----

=== Совместимость типов объединений

Два объединения совместимы, если и только если они объявлены в одной области видимости с одним и тем же тегом и имеют одинаковый набор полей.

Два объединения с одинаковыми полями, но разными тегами — это **разные типы**:

[source,c]
----
union A { int x; };
union B { int x; };

union A a = {1};
union B b = a;    /* ошибка: разные типы */
----

NOTE: Это следствие **номинативного тождества типов** в C.

=== Примеры использования

==== Tagged union

Объединение с дополнительным полем-тегом, указывающим, какое поле активно:

[source,c]
----
enum Type { INT_VAL, DOUBLE_VAL, STRING_VAL };

struct Variant {
    enum Type type;
    union {
        int    i;
        double d;
        char   s[16];
    } value;
};

void print_variant(struct Variant v) {
    switch (v.type) {
        case INT_VAL:    printf("%d\n", v.value.i); break;
        case DOUBLE_VAL: printf("%f\n", v.value.d); break;
        case STRING_VAL: printf("%s\n", v.value.s); break;
    }
}
----

Tagged union — это основной способ реализовать в C универсальный тип данных (наподобие Variant в некоторых других языках).

==== Экономия памяти

Этот прием может оказаться полезным, когда поля используются взаимоисключающе:

[source,c]
----
struct Event {
    enum { MOUSE, KEYBOARD, TIMER } type;
    union {
        struct { int x, y; } mouse;
        struct { int key; }    keyboard;
        struct { long time; }  timer;
    } data;
};
----

Без объединения размер `data` был бы суммой размеров всех полей; с объединением объект имеет максимальный размер из всех перечисленных вариантов.

==== Type punning

Объединения часто используются для **type punning** (переинтерпретации битового представления одного типа как другого):

[source,c]
----
union FloatInt {
    float f;
    int   i;
};

union FloatInt u = { .f = 3.14f };
int bits = u.i;   /* битовое представление float как int */
----

Это полезно для низкоуровневой работы (сериализация, отладка и пр.), но требует понимания правил активного члена
и может оказаться непереносимым.

==== Дискриминант в анонимных объединениях

С анонимными объединениями (C11) tagged union становится ещё удобнее:

[source,c]
----
struct Value {
    int tag;
    union {
        int    i;
        double d;
        char  *s;
    };
};

struct Value v = { .tag = 1, .d = 3.14 };
/* Прямой доступ: v.d, v.i, v.s — без промежуточного .value */
----

=== Резюме

Объединение в языке C — это агрегатный тип, размещающий поля **поверх друг друга** в одной области памяти.

* *Домен*: объединение доменов полей, с ограничением: активно ровно   одно поле в каждый момент времени.
* *Операции*: 
** доступ к полям через `.` и `->`,
** присваивание целиком,
** передача и возврат по значению,
** агрегатная и именованная инициализация.
* *Не определены*:
** сравнение по содержимому,
** арифметические и побитовые   операции.
* *Размер*: равен размеру наибольшего поля, возможно с padding для выравнивания.
* *Активный член*: поле, записанное последним; чтение неактивного члена ограничено правилами стандарта (C23).
* *Битовые поля*: допустимы, но порядок упаковки зависит от реализации.
* *Гибкий массив*: недопустим в объединениях.
* *Анонимные объединения* (C11): поля видны напрямую во внешней структуре.

Ключевые применения:

* **tagged unions** — реализация полиморфизма в C;
* **экономия памяти** — когда поля используются взаимоисключающе;
* **type punning** — переинтерпретация битового представления (с осторожностью).

Понимание объединений необходимо для работы с полиморфными данными, сериализацией, низкоуровневой манипуляцией  битовыми представлениями и взаимодействия с аппаратным обеспечением в C.
