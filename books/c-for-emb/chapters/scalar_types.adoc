== Скалярные типы

**Скалярным** называется тип, объекты которого содержат ровно одно значение, в отличие от **агрегатных** типов (массивов и структур), объекты которых содержат множество значений, организованных определённым образом.

Скалярные типы включают в себя *арифметические* типы и типы-*указатели*. Арифметические типы, в свою очередь,
подразделяются на *целочисленные* и *вещественные*.

То, что скаляр содержит одно значение, определяет характер операций над ним: присваивание копирует значение целиком, сравнение сопоставляет два значения, передача в функцию передаёт одно значение.

=== Целочисленные типы (`int`)

К целочисленным типам относятся:

* *символьные типы*: `char`, `signed char`, `unsigned char`;
* *целые со знаком*: `signed char`, `short`, `int`, `long`, `long long`;
* *целые без знака*: `unsigned char`, `unsigned short`, `unsigned int`,   `unsigned long`, `unsigned long long`;
* *булев тип*: `bool` (в C99/C11/C17 — `_Bool`);
* *перечисления*: `enum`;
* *произвольные целые*: `_BitInt(N)` и `unsigned _BitInt(N)` (с C23).

Тип `char` может быть как знаковым, так и беззнаковым; это определяет конкретная реализация.

Типы `char`, `signed char` и `unsigned char` совместно называются *символьными типами* (character types).

NOTE: `char`, `signed char` и `unsigned char` -- это три *разных* типа!

==== Домен

Ранее (TBD) упоминалось, что в языке C не специфицируется точный размер определенного типа в байтах. Вместо этого стандарт гарантирует лишь **минимальный** домен значений для каждого типа:

[cols="1,2,2",options="header"]
|===
| Тип | Минимальный знаковый домен | Беззнаковый аналог

| `char` | −127 … 127 *или* 0 … 255 | знак зависит от реализации
| `signed char` | −127 … 127 | `unsigned char`: 0 … 255
| `short` | −32 767 … 32 767 | 0 … 65 535
| `int` | −32 767 … 32 767 | 0 … 65 535
| `long` | −2 147 483 647 … 2 147 483 647 | 0 … 4 294 967 295
| `long long` | −2^63^ + 1 … 2^63^ − 1 | 0 … 2^64^ − 1
|===

На многих платформах домены шире минимума. Ниже приведены домены для некоторых распространенных *моделей данных*:

[cols="2,4,2,2,2,2,3,2",options="header"]
|===
| Модель | Применение | `char` | `short` | `int` | `long` | `long long` | `void*`

| LP32 | Win16 API | 8 | 16 | 16 | 32 | 64 | 4
| ILP32 |  Win32 API, Unix, Linux, macOS | 8 | 16 | 32 | 32 | 64 | 4
| LLP64 |  ARM (AArch64),  Windows API (x64) | 8 | 16 | 32 | 32 | 64 | 8
| LP64 |  Unix, Linux, macOS (64 bit) | 8 | 16 | 32 | 64 | 64 | 8
|===

Для случаев, когда программисту требуется *точно* знать размер объекта в байтах, в заголовке `<stdint.h>` определены типы `int8_t`, `int16_t`, `int32_t`, `int64_t` и их беззнаковые аналоги, а также семейства `int_leastN_t` и `int_fastN_t` (TBD).

==== Операции

IMPORTANT: integer promotions (TBD)

Над целочисленными типами определены следующие операции.

===== Унарные операции

* `+` -- унарный плюс (не влияет на значение операнда);
* `-` -- унарный минус (меняет знак операнда на противоположный).

===== Арифметические операции

* `+` -- сложение;
* `-` -- вычитание;
* `*` -- умножение;
* `/` -- целочисленное деление (дробная часть отбрасывается);
* `%` -- остаток от деления (взятие по модулю)

===== Побитовые операции

* `&` -- поразрядное "И";
* `|` -- поразрядное "ИЛИ";
* `^` -- поразрядное "Исключающее ИЛИ";
* `~` -- поразрядное дополнение (инверсия);
* `<<` -- сдвиг влево;
* `>>` -- сдвиг вправо.

===== Операции сравнения

* `<` -- меньше;
* `<=` -- меньше или равно;
* `>` -- больше;
* `>=` -- больше или равно;
* `==` -- равно;
* `!=` -- не равно.

===== Инкремент и декремент

* `++` -- инкремент (увеличение на единицу);
* `--` -- декремент (уменьшение на единицу.

===== Логические операции

* `&&` -- логическое "И";
* `||` -- логическое "ИЛИ";
* `!` -- отрицание.

===== Присваивание

* `=` -- объекту, находящемуся слева от оператора присваивания, присваивается значение выражения, находящегося справа.

[IMPORTANT]
====
Существует также другая форма оператора присваивания: `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=`.

Если представить его в общем виде как `?=`, где символ `?` заменяет любой из вышеперечисленных опереторов, то запись

[source,c]
----
X ?= Y;
----

почти эквивалентна

[source,c]
----
X = X ? Y;
----

за исключением того, что `X` вычисляется только один разfootnote:[Это различие существенно, если при вычислении значения `X` возникают побочные эффекты.].
====

==== Особенности поведения

===== Переполнение

При выполнении операций над целочисленными типами возможен выход за границы домена (переполнение). Поведение при переполнении принципиально различается для знаковых
и беззнаковых типов:

[source,c]
----
unsigned int u = UINT_MAX;
u + 1;          /* 0: арифметика по модулю 2^N */

int i = INT_MAX;
i + 1;          /* неопределённое поведение */
----

исходить из того, что оно не происходит (что используется для оптимизаций).
Для беззнаковых типов арифметика *всегда* выполняется по модулю 2^N^ *по определению. Для знаковых типов переполнение является *неопределённым поведением*, и компилятор не пытается отследить эту ситуацию.

===== Деление и остаток

Оператор `/` для целых *не округляет*, а просто *отбрасывает* дробную часть в сторону нуля:

[source,c]
----
 7 /  2;    /*  3 */
-7 /  2;    /* -3 */
 7 / -2;    /* -3 */
-7 / -2;    /*  3 */
----

Оператор `%` возвращает остаток такой, что `(a / b) * b + a % b == a`.

Деление на ноль и взятие остатка от деления на ноль приводят к неопределённому поведению.

===== Сдвиги

* Сдвиг на отрицательную величину или на величину, не меньшую ширины типа, приводит к неопределённому поведению.
* Сдвиг отрицательного знакового числа влево приводит к неопределённому поведению в C11/C17, определено в C23 при условии, что результат представим. (TBD)
* Сдвиг вправо знаковых отрицательных чисел вызывает поведение, определенное реализацией (обычно арифметический сдвиг с сохранением знака).


==== Продвижение целых

Перед выполнением большинства операций над целочисленными типами выполняется **продвижение целых** (integer promotions).

Если тип операнда имеет меньшую разрядность, чем `int`, он преобразуется к `int` (если `int` может представить все значения исходного типа) либо к `unsigned int` (в противном случае).

К операндам, к которым применяется продвижение, относятся:

* операнды унарных операторов `+`, `-`, `~`;
* операнды `char` и `short` (любого знака) в бинарных операторах;
* операнды битовых полей, если их тип имеет меньшую разрядность, чем `int`;
* условие оператора `?:`.

Примеры:

[source,c]
----
unsigned char a = 255;
unsigned char b = 1;

a + b;        /* 256, а не 0 */
----

Операнды `a` и `b` продвигаются до `int`, поэтому сложение выполняется в домене `int` и дает в результате значение 256. Приведение обратно к `unsigned char` не происходит.

[source,c]
----
unsigned char c = 0xFF;
~c;           /* не 0x00, а 0xFFFFFF00 (на 32-битном int) */
----

Оператор `~` применяется уже после продвижения, поэтому инвертируются все 32 бита.

[source,c]
----
unsigned char x = 0;
-x;           /* тип результата — int, значение 0 */
----

Унарный минус возвращает `int`, а не `unsigned char`.

WARNING: Продвижение целых — одна из наиболее частых причин «неожиданного» поведения в программах на C. Внимательно разберитесь в этом.

=== Перечисления

==== Семантика

Перечисление (`enum`) фактически представляет собой разновидность целочисленного типа, значения которого
идентифицируются именованными константами-перечислителями.

IMPORTANT: Перечисление **не вводит** нового
способа представления данных; оно вводит *имена* для целых чисел.

Главное назначение перечислений -- сделать код читаемым и понятным. Вместо "магических чисел" используются символические имена.

[source,c]
----
enum Color { RED, GREEN, BLUE };

enum Color c = GREEN;   /* вместо «магического числа» 1 */
----

==== Синтаксис и правила нумерации

Общая форма объявления:

[source,c]
----
enum имя { список-перечислителей };
----

Правила вычисления значений:

. Если у первого перечислителя нет явно заданного посредством `=` значения, его значение равно **0**.
. Если у очередного перечислителя нет `=`, его значение на **единицу больше**   значения предыдущего.
. Перечислитель с `=` получает значение указанного константного выражения; дальнейший отсчёт продолжается от него.

[source,c]
----
enum Example {
    A,          /* 0 — правило 1 */
    B,          /* 1 — правило 2 */
    C = 10,     /* 10 — правило 3 */
    D,          /* 11 */
    E = -5,     /* -5: отрицательные значения допустимы */
    F,          /* -4 */
    G = A,      /* 0: дубликаты значений допустимы */
    H,          /* 1 */
                /* завершающая запятая разрешена начиная с C99 */
};				
----

Выражение, задающее значение перечислителя, должно быть **целым константным выражением**. В нём допустимы литералы, ранее объявленные перечислители, оператор `sizeof`, приведения констант, `_Static_assert`-совместимые вычисления:

[source,c]
----
enum Limits {
    WORD_BYTES  = sizeof(long),         /* sizeof — константное выражение */
    BUF_WORDS   = 64,
    BUF_BYTES   = BUF_WORDS * WORD_BYTES
};
----

Поскольку значения перечислителей — целые константные выражения, их можно использовать всюду, где язык требует константы: 

* в размерах массивов,
* в метках `case`,
* в размерах битовых полей,
* в статических инициализаторах.

==== Домен 

Переменная перечислимого типа совместима с некоторым целочисленным типом (выбираемым реализацией).

.Замкнутость домена перечислений
****
В контексте типов «замкнутость» означает, что тип определяет **строго ограниченное** множество допустимых значений, и выход за его границы является ошибкой или неопределённым поведением.

В C перечислимый тип **не является** замкнутым множеством. Это означает, что переменная перечислимого типа в C может хранить **любое значение**, представимое в совместимом целочисленном типе, а не только значения, перечисленные в списке перечислителей.

[source,c]
----
enum Color { RED, GREEN, BLUE };    // 0, 1, 2

enum Color c = RED;
c = 42;             // допустимо: значение представимо в совместимом типе
c = GREEN | BLUE;   // 3 — тоже допустимо, хотя такого перечислителя нет
c++;                // допустимо: инкремент целочисленного типа
c = -100;           // допустимо, если совместимый тип — знаковый
----

Практические последствия:

. Нельзя полагаться на то, что переменная перечислимого типа содержит одно из перечисленных значений.
. При чтении значений из файла, сети или разделяемой памяти необходимо явно проверять их допустимость.
. Побитовые операции над перечислениями дают значения вне списка перечислителей, и это **законно**.
. Следует использовать `switch` с `default` для обработки неожиданных значений.
. Следует включать предупреждения компилятора `-Wswitch` и `-Wenum-conversion`, чтобы обнаруживать смешение разных перечислений.

IMPORTANT: Перечисление в C — это **именованный целочисленный тип с подсказками**, а не строгая проверка принадлежности множеству. Программист обязан сам следить за тем, чтобы значения оставались в ожидаемом диапазоне.
****

[CAUTION]
====
* Размер объекта перечислимого типа не задан стандартом и может отличаться на разных платформах и даже при разных ключах компиляции.
* Знаковость перечисления зависит от допустимого набора значений. Перечисление с отрицательными значениями не может быть совместимо с беззнаковым типом.
====

[NOTE]
====
Распространённые реализации ведут себя по-разному.

* GCC и Clang по умолчанию используют `unsigned int` для перечислений с неотрицательными значениями и `int` при наличии отрицательных; ключ `-fshort-enums` заставляет выбирать наименьший вмещающий тип.
* MSVC всегда использует `int`.
====

==== Множество операций

Над перечислениями определены те же операции, что и над целыми: арифметика, сравнения, присваивания. При выполнении операций перечисления продвигаются до целого типа.

==== Анонимные перечисления

Перечисление может быть объявлено **без тега** — так называемое *анонимное перечисление*:

[source,c]
----
enum { RED, GREEN, BLUE };
----

Такое объявление не создаёт именованного типа, но **создаёт перечислители** в текущей области видимости. Они ведут себя как обычные целые константы:

[source,c]
----
enum {
    BUF_SIZE   = 1024,
    MAX_ERRORS = 10,
    VERSION    = 3
};

char buffer[BUF_SIZE];
int errors = 0;

if (errors > MAX_ERRORS) {
    /* ... */
}
----

===== Использование

Анонимные перечисления используются как **альтернатива `#define`** для групп связанных целочисленных констант. Такая альтернатива обладает рядом преимуществ:

* **Видимость отладчику**: перечислители сохраняются в отладочной информации, в отличие от макросов, которые исчезают после препроцессора.
* **Лексическая область видимости**: перечислители подчиняются обычным правилам области видимости C, а не действуют до конца файла, как макросы.
* **Последовательная нумерация**: если значения не заданы явно, они автоматически увеличиваются, что удобно для счётчиков и кодов.
* **Группировка**: несколько связанных констант объединяются в одно объявление, что улучшает читаемость кода.

[source,c]
----
/* Вместо множества #define */
#define RED   0
#define GREEN 1
#define BLUE  2

/* Лучше: анонимное перечисление */
enum { RED, GREEN, BLUE };
----

===== Ограничения

Поскольку анонимное перечисление не имеет имени, нельзя объявить переменную этого типа:

[source,c]
----
enum { LOW, MEDIUM, HIGH };

/* enum ??? priority = LOW; */   /* невозможно: у перечисления нет имени */
int priority = LOW;              /* допустимо: перечислитель — это int */
----

Если требуется создание типа, необходимо использовать именованное перечисление или `typedef`:

[source,c]
----
typedef enum { LOW, MEDIUM, HIGH } Priority;
Priority p = HIGH;
----

===== Сравнение с именованными перечислениями

[cols="1,2,2",options="header"]
|===
| Свойство | Анонимное `enum { ... }` | Именованное `enum Name { ... }`

| Создаёт тип | нет | **да**
| Можно объявить переменную | нет | **да**
| Перечислители видны | **да** | **да**
| Альтернатива `#define` | **да** | частично
| Область видимости перечислителей | лексическая | лексическая
| Фиксированный базовый тип (C23) | **да** | **да**
|===

===== Практические правила

* Используйте **анонимные перечисления** для групп связанных целочисленных   констант, когда типизация не требуется: коды ошибок, флаги, индексы.
* Используйте **именованные перечисления**, когда нужна типизация,   проверка полноты в `switch` или передача значений как параметров функций.
* Избегайте смешения: если константы логически связаны с типом, используйте именованное перечисление; если это просто набор чисел — анонимное.

==== Особенности поведения

===== Типы перечисления и перечислителей

До стандарта C23 перечислители всегда имеют тип `int` *независимо* от того, с каким типом совместимо само перечисление. Это порождает неочевидное противоречие:

[source,c]
----
enum Small { S_A, S_B, S_C };
enum Small s;

sizeof(S_A);    /* sizeof(int) — перечислитель имеет тип int */
sizeof s;       /* размер перечислимого типа, выбираемый реализацией */
----

При компиляции с `-fshort-enums` эти два выражения могут дать разные результаты: например, `sizeof(S_A)` равно 4, а `sizeof s` 1.

===== Область видимости перечислителей

Перечислители -- это **обычные идентификаторы** той области видимости, в которой объявлено перечисление. Тег перечисления их не ограничивает.

[source,c]
----
enum Color { RED, GREEN, BLUE };
enum Signal { RED, YELLOW };    /* ошибка: RED уже объявлен в этой области */

int RED;                        /* ошибка: то же имя в той же области */

void f(void) {
    int RED = 5;                /* допустимо: внутренний блок, имя скрыто */
}
----

[IMPORTANT]
====
Сам *тег* перечисления живёт в отдельном пространстве имён тегов, поэтому он не конфликтует с переменными:

[source,c]
----
enum Color { C_RED, C_GREEN };
int Color;                      /* допустимо: тег и переменная — разные пространства */
----
====

На практике для сокращения записи широко применяется `typedef`:

[source,c]
----
typedef enum { LOW, MEDIUM, HIGH } Priority;
Priority p = HIGH;              /* слово enum не требуется */
----

===== Смешивание перечислений

Все перечислимые типы являются целочисленными. Поэтому присваивание значения одного перечисления переменной другого формально допустимо и даже не требует приведения:

[source,c]
----
enum Color  { RED, GREEN, BLUE };
enum Status { OK, FAIL };

enum Status st = RED;       /* допустимо в C, хотя смысл утрачен */
----

Это одно из слабых мест системы типов C. Некоторые компиляторы обнаруживают такие смешения при включённых соответствующих предупреждениях (например, `-Wenum-conversion` в GCC/Clang). При работе с перечислениями обязательно нужно использовать эти ключи.

===== Перечисления и оператор switch

Перечисления особенно удобны в `switch`: компилятор способен проверить, все ли перечислители обработаны.

[source,c]
----
enum Color { RED, GREEN, BLUE };

const char *name(enum Color c) {
    switch (c) {
        case RED:   return "red";
        case GREEN: return "green";
        case BLUE:  return "blue";
    }
    return "?";     /* значения вне списка всё же возможны */
}
----

При отсутствии одной из меток GCC и Clang с ключом `-Wswitch` выдают предупреждение. Это единственный механизм, отчасти компенсирующий открытость домена перечисления.

WARNING: Наличие ветви `default` подавляет такое предупреждение. Если важна проверка полноты, `default` лучше не писать, а обработку «невозможных» значений вынести после `switch`.

===== Перечисления в стандарте C23

Стандарт C23 (ISO/IEC 9899:2024) существенно расширил возможности перечислений, устранив две давние проблемы: неопределённость представления и ограничение диапазона значений.

====== Фиксированный базовый тип

В C23 после имени перечисления можно указать **базовый тип** (fixed underlying type) через двоеточие:

[source,c]
----
enum Byte : unsigned char {
    B_MIN = 0,
    B_MAX = 255
};

_Static_assert(sizeof(enum Byte) == 1, "expected one byte");
----

Теперь перечислимый тип совместим не с «некоторым типом по выбору реализации», а с явно указанным типом. Это даёт:

* **предсказуемый размер** объекта;
* **предсказуемую знаковость**;
* **стабильный ABIfootnote:[ABI (Application Binary Interface) — это «контракт» на уровне скомпилированного машинного кода о том, как разные части программы (например, ваше приложение и системная библиотека) взаимодействуют друг с другом. **Не путать с API!**]** — двоичное представление структур с перечислениями перестаёт зависеть от ключей компиляции;
* возможность использовать перечисления в протоколах и аппаратных регистрах без опасений.

[source,c]
----
struct Header {
    enum Byte  kind;        /* ровно 1 байт */
    enum Flags : unsigned int flags;
};
----

Базовым типом может быть `char`, знаковый или беззнаковый целый тип.

====== Значения вне диапазона int

До C23 значение перечислителя обязано было быть представимо в типе `int`. Это делало невозможными, например, перечисления 64-битных масок.

В C23 ограничение снято: допустимы значения, выходящие за диапазон `int`, что естественно в сочетании с соответствующим фиксированным базовым типом.

[source,c]
----
/* C17: ошибка — значение не представимо в int */
/* C23: допустимо */
enum Mask : unsigned long long {
    M_LOW  = 1ULL << 0,
    M_HIGH = 1ULL << 40,
    M_ALL  = ~0ULL
};
----

Соответственно изменились и правила определения типа самих перечислителей: он больше не обязан всегда быть `int`. Если базовый тип указан, перечислители соотносятся с ним; если не указан и значение представимо в `int`, сохраняется прежнее поведение.

====== Объявление без определения

Указание базового типа делает объявление перечисления **полным** даже без списка перечислителей. Это позволяет объявить тип заранее, а определить позже:

[source,c]
----
enum Handle : int;              /* C23: тип полон, размер известен */

struct Registry {
    enum Handle key;            /* допустимо: тип уже полный */
};

enum Handle : int {             /* определение */
    H_NONE  = -1,
    H_FIRST = 0
};
----

В C17 подобный приём был невозможен: перечислимый тип становился полным только после списка перечислителей.

====== Сводка изменений

[cols="2,2,2",options="header"]
|===
| Аспект | До C23 | C23

| Совместимый тип | Выбирается реализацией | Можно задать явно: `enum E : T`
| Размер объекта | Не определён стандартом | Определён при заданном базовом типе
| Диапазон значений перечислителей | Должен помещаться в `int` | Ограничение снято
| Тип перечислителя | Всегда `int` | Зависит от значения и базового типа
| Объявление без списка | Неполный тип, вне стандарта | `enum E : T;` — полный тип
| Анонимные перечисления с базовым типом | нет | `enum : T { ... }`
| Область видимости перечислителей | Объемлющая область | Без изменений
| Замкнутость домена | Домен открыт | Без изменений
|===

==== Практические приёмы

===== Счётчик числа элементов

Завершающий перечислитель-«часовой» даёт количество значений, которое автоматически остаётся корректным при расширении списка:

[source,c]
----
enum Month {
    JAN, FEB, MAR, APR, MAY, JUN,
    JUL, AUG, SEP, OCT, NOV, DEC,
    MONTH_COUNT             /* 12 */
};

static const char *month_name[MONTH_COUNT] = {
    "январь", "февраль", "март",     "апрель", "май",    "июнь",
    "июль",   "август",  "сентябрь", "октябрь","ноябрь", "декабрь"
};
----

WARNING: Приём работает корректно **только при последовательной нумерации без пропусков**. Если значения заданы явно, `MONTH_COUNT` перестаёт играть роль счетчика.

===== Битовые флаги

Перечисление со степенями двойки удобно для наборов битовых флагов.

Комбинация флагов даёт значение вне списка перечислителей (в C это законно):

[source,c]
----
enum Perm : unsigned int {      /* базовый тип — синтаксис C23 */
    PERM_NONE  = 0,
    PERM_READ  = 1u << 0,
    PERM_WRITE = 1u << 1,
    PERM_EXEC  = 1u << 2
};

enum Perm p = PERM_READ | PERM_WRITE;

if (p & PERM_WRITE) {
    /* запись разрешена */
}
p |= PERM_EXEC;
p &= ~PERM_READ;
----

NOTE: Здесь лучше указывать беззнаковый базовый тип; побитовые операции над знаковыми значениями требуют осторожности.

===== X-макросы: единый источник имён

Иногда требуется получать доступ не только к значению перечислителя, но и к его идентификатору. Чтобы избежать рутинной ручной работы для создания таблицы имен (которую к тому же придется потом поддерживать), можно воспользоваться макросом:

[source,c]
----
#define COLORS(X)   X(RED) X(GREEN) X(BLUE)

#define AS_ENUM(n)   n,
#define AS_STRING(n) #n,

enum Color { COLORS(AS_ENUM) };
static const char *color_name[] = { COLORS(AS_STRING) };

#undef AS_ENUM
#undef AS_STRING
----

Добавление нового цвета в макрос `COLORS` автоматически расширяет и перечисление, и таблицу имён.

===== Перечисления, `#define` и `static const`

Три способа ввести именованную целую константу в C решают разные задачи:

[cols="1,2,2,2",options="header"]
|===
| Свойство | `enum` | `#define` | `static const int`

| Виден препроцессору | нет | **да** | нет
| Виден отладчику | **да** | обычно нет | **да** |
| Создаёт отдельный тип | **да** | нет | нет
| Проверка полноты в `switch` | **да** | нет | нет
| Является константным выражением | **да** | **да** | нет
| Пригоден для размера массива | **да** | **да** | нет (кроме VLA)
| Занимает память | нет | нет | обычно да
| Область видимости | лексическая | до `#undef` / конца файла | лексическая
|===

Правила выбора:

* связанные наборы значений, состояния, коды ошибок -- `enum`;
* константы, нужные препроцессору или сборке -- `#define`;
* единичные типизированные константы, адресуемые через указатель -- `static const`.


==== Резюме

Перечисление в языке C — это **именованный целочисленный тип**, а не строгое алгебраическое множество.

* *Семантика*: имена для целых констант-перечислителей плюс отдельный тег типа.
* *Домен*: значения перечислителей задают «ожидаемое» подмножество, но фактический домен определяется совместимым целочисленным типом   и остаётся открытым.
* *Операции*: полный набор целочисленных операций; перечислители   пригодны всюду, где нужно целое константное выражение.
* *Анонимные перечисления*: удобный способ ввести группу связанных целочисленных констант без создания отдельного типа — альтернатива `#define` с сохранением области видимости и видимости отладчику.
* *Особенности*:
** продвижение целых,
** тип перечислителей `int` (до C23),
** отсутствие собственной области видимости,
** невидимость препроцессору,


=== Вещественные типы

К вещественным типам относятся:

* `float` — 32-битный двоичный формат (IEC 60559 binary32);
* `double` — 64-битный двоичный формат (IEC 60559 binary64);
* `long double` — расширенный формат, зависящий от реализации
  (80-битный на x86, binary128 на ARM, иногда совпадает с `double`);
* с C23 в основном тексте — децимальные типы `_Decimal32`,
  `_Decimal64`, `_Decimal128`.

==== Домен
  
Домен включаеn:

* нормализованные конечные числа;
* субнормальные (денормализованные) числа;
* два нуля: `+0` и `−0`;
* две бесконечности: `+∞` и `−∞`;
* множество NaN (quiet и signaling).

IMPORTANT: Важно помнить, что **домен вещественного типа включает не все вещественные числа**, а конечное множество представимых чисел вместе со специальными значениями (±0, ±∞, NaN). Это естественное следствие огранниченного числа разрядов для представления таких чисел. Децимальные типы обладают иным доменом: в них точно представимы десятичные дроби вида `0.1`, что делает их пригодными для финансовых вычислений.

[source,c]
----
0.1 + 0.2 == 0.3;       /* false: 0.1 и 0.2 не представимы точно */
NAN == NAN;             /* false: NaN не равен ничему */
+0.0 == -0.0;           /* true: нули равны при сравнении */
1.0 / 0.0;              /* +inf, а не аварийное завершение */
----

==== Операции

Над вещественными типами определены следующие операции.

===== Унарные операции

* `+` -- унарный плюс (не влияет на значение операнда);
* `-` -- унарный минус (меняет знак операнда на противоположный).

===== Арифметические операции

* `+` -- сложение;
* `-` -- вычитание;
* `*` -- умножение;
* `/` --  деление.

===== Операции сравнения

* `<` -- меньше;
* `<=` -- меньше или равно;
* `>` -- больше;
* `>=` -- больше или равно;
* `==` -- равно;
* `!=` -- не равно.

===== Присваивание

* `=` -- объекту, находящемуся слева от оператора присваивания, присваивается значение выражения, находящегося справа.

[IMPORTANT]
====
Как и для целочисленных типов, поддерживаются формы оператора присваивания +=`, `-=`, `*=`, `/=`.

==== Особенности поведения

При применении побитовых операций (как и арифметических) значение операндов продвигается до `int`, что приводит к неочевидным на первый взгляд последствиям:

[source,c]
----
true + true;    /* 2, тип int */
~false;         /* -1 (все биты инвертированы в promoted int) */
----

Любое скалярное значение при приведении к `bool` принимает значение 0 или 1:

[source,c]
----
bool a = 42;        /* true  */
bool b = 0.0;       /* false */
bool c = NULL;      /* false */
----

==== Эволюция

* В ранних версиях языка в качестве логических значений использовались целочисленные (`int`).
* В C99 введён тип `_Bool`; идентификаторы `bool`, `true`, `false` определены как макросы в заголовке `<stdbool.h>`.
* В C23 `bool`, `true`, `false` стали ключевыми словами. Заголовок `<stdbool.h>` сохранён для совместимости с предыдущими версиями.


=== Указатели

*Указатель* -- это скалярный производный тип, значение которого обеспечивает *доступ* к объекту (или функции) некоторого другого типа.

[IMPORTANT]
====
Очень часто можно встретить мнение, что указатель представляет собой *адрес* объекта, на который он указывает. Это ошибочное мнение. Хотя для многих современных архитектур с плоской моделью памяти указатель действительно реализуется как адрес объекта в памяти, в общем случае это не так. Например, в реальном режиме микропроцессора i8086 20-разрядный физический адрес вычисляется как сумма 16-разрядного базового адреса сегмента, сдвинутого влево на 4 бита, и 16-разрядного смещения в пределах сегмента, при этом *разные* пары сегмент-смещение могут указывать на *один и тот же* физический адрес. Существуют и другие варианты (например, для вычисления адреса используется индекс в таблице дескрипторов страниц памяти).

Поскольку мы решили учиться писать *портабельный* код на C, который корректно работает на *любой* архитектуре, мы не должны закладываться на знание частных особенностей конкретной архитектуры. Следует рассматривать указатель как **абстракцию**, обеспечивающую доступ к сущности некоторым способом, зависящим от реализации на данной платформе. Поэтому корректно говорить, что указатель *указывает* (points to) на объект, а не "равен его адресу".
====

Объявление указателя имеет вид:

[source,c]
----
T *p;
----

где `T` -- тип объекта, на который он указывает.

==== Домен

**Домен указателя `T *`** — это множество значений, каждое из которых обеспечивает **доступ** (reference) к сущности типа `T` согласно семантике языка C.

Указатель `T *` может принимать следующие значения:

. Значение, обеспечивающее доступ к объекту типа `T` (или функции, если `T` — функциональный тип). Это значение указывает на существующий объект или функцию.
. Значение, указывающее на позицию **непосредственно за последним элементом массива** объектов типа `T`. Это специальное значение; его можно использовать в операциях арифметики указателей и сравнения, но запрещено *разыменовывать*.
. Нулевое значение указателя (null pointer value) — значение, которое *гарантированно* не обеспечивает доступ ни к какому объекту или функции.

Значения, обеспечивающие доступ к объектам других типов, *не входят* в домен `T *`; однако они могут быть *приведены* к типу `T *` (с использованием операции приведения).

==== Операции

===== Присваивание

[source,c]
----
`p = q`;
----

где `p` и `q` -- указатели.

Указатель может быть присвоен:

* указателю того же типа;
* указателю типа `void *` и обратно -- неявно, без приведения (поэтому `void *` может использоваться как "указатель общего назначения");
* указателю на *совместимый* тип;
* специальному значению *нулевого указателя* -- константе `NULL` (макрос из `<stddef.h>`) или целочисленной константе `0`footnote:[Как мы уже знаем, указатель *не* является адресом, поэтому в общем случае производится неявное преобразование нуля в *представление* нулевого указателя для данной платформы (слабая типизация языка это позволяет).].
+
NOTE: Начиная со стандарта C23 в язык введено значение `nullptr` (см. TBD), имеющее специальный тип `nullptr_t`.

===== Разыменование

Разыменование (`*p`) предоставляет доступ к объекту, на который указывает `p`.

===== Доступ к полю структуры

Если `p` указывает на структуру, в состав которой входит поле `member`, то операция `p->member` предоставляет доступ к этому полю.

NOTE: Фактически это эквивалентно `(*p).member`.

===== Арифметика

Арифметические операции над указателями тесно связаны с понятием *массива*. TBD

* Если `K` -- значение, которое можно привести к целому типу, то `p + K` и `p - K` указывают на объект, смещенный относительно `p` на `K` *элементов* соответственно вправо или влево (то есть на `n * sizeof(T)` *байт*).
* `++p`, `p++`, `--p`, `p--` -- частный случай смещения на *один* элемент (при `K == 1`).
* `p - q` -- расстояние в *элементах* между двумя указателями (определено только в случае, если оба указателя ссылаются на элементы *одного* массива или на элемент сразу за его концом). Для представления разности указателей используется специально созданный для этой цели знаковый целочисленный тип, который определён в заголовочном файле `<stddef.h>`.

===== Сравнение

* `p == NULL` -- сравнение с нулевым указателем (используется для проверки валидности указателя);
* `p == q` -- сравнение указателей на *равенство*, то есть проверка, указывают ли два указателя на один и тот же объект (или оба являются нулевыми);
, `p != q` -- сравнение указателей на *неравенство*.

[CAUTION]
====
Для следующих операций сравнения результат определен только в следующих случаях:

* когда оба указывают на элементы одного массива (или на элемент сразу за его концом);
* когда оба указывают на поля одной структуры.

В остальных случаях результат не определён.
====

* `p < q`;
* `p > q`;
* `p <= q`;
* `p >= q

===== Приведение к другим типам

====== Приведение к другим типам указателей

Указатели можно явно приводить к другим типам указателей:

[source,c]
----
A *pa;
...
B *pb = (B*)pa;
----

При этом следует отдавать себе отчет о проблемах, к которым может привести такое приведение.

Во-первых, довольно легко получить неопределенное поведение. Например, в приведенном выше примере может оказаться, что значение `*pa` имеет битовый паттерн, недопустимый для типа `B`. В этом случае при попытке разыменовать `pb` возникнет неопределенное поведение.

Во-вторых, даже если удастся избежать неопределенного поведения, остается вероятность получить поведение, зависящее от платформы. Например:

[source,c]
----
void process_byte(const uint8_t *);
...
uint32_t i = 0x12345678L;
...
uint8_t *pb = (uint8_t *)&i;
for (size_t n = 0; n < 4; ++n)
{
    process_byte(pb++);
}
----

В данном случае мы предприняли наивную попытку интерпретировать 32-битовое целое беззнаковое число как массив из четырех смежных байтов. Проблема состоит в том, что на машинах little-endian и big-endian этот код будет работать по-разному, что будет неожиданным и крайне неприятным сюрпризом для его автора.

====== Приведение к целым типам

Довольно распространенная ошибка -- попытка привести значение указателя к типу `int`. Она обусловлена, по-видимому, тем, что на 8- и 16-разрядных платформах, с которых многие начинают свой путь в эмбеддинг, диапазон адресуемой памяти не превышает диапазон целого типа, поэтому подобные трюки обычно сходят с рук и закрепляются в памяти. Однако на 64-разрядных платформах это уже не пройдет (причина указана в TBD). Получаем проблему непереносимости кода между платформами.

Для решения этой проблемы в заголовочном файле `<stdint.h>` из стандартной библиотеки предусмотрены два специальных целочисленных типа достаточной для представления указателя на данной платформе ширины:

* `intptr_t` -- знаковый,
* `uintptr_t` -- беззнаковый.

Их использование дает безопасный переносимый код.

===== Примеры операций с указателями

[source,c]
----
int a[10];
int *p = a;       /* присваивание: указатель на массив -> указатель на int */
int *q = p;       /* присваивание указателей одного типа */
void *v = p;      /* неявное преобразование в void * */

p + 1;            /* смещение на sizeof(int) байт */
p == q;           /* истинно: оба указывают на a[0] */
p < &a[5];        /* истинно: оба внутри одного массива */
p == NULL;        /* ложно: p не является нулевым указателем */
----

==== Указатель на объект неизвестного типа

Среди разных типов указателей есть один совершенно особый случай: это `void *` -- указатель на объект неизвестного типа. Он неявно преобразуется в любой объектный указатель и обратно.

В стандарте языка размер "пустого" типа `void` (т. е. `sizeof(void)`) не определен. Как неизбежное следствие этого, арифметика над `void *` также не определена, поскольку для вычисления величины смещения необходимо знать размер объекта, на который указывает исходный указатель. Однако некоторые реализации используют расширение стандарта, трактуя `sizeof(void)` как 1). Использование подобных расширений крайне не рекомендуется без настоятельной необходимости, поскольку использующий их код теряет переносимость.








== Обычные арифметические преобразования

Когда в бинарной операции участвуют два операнда разных целочисленных
или вещественных типов, сначала к обоим применяются продвижения целых,
а затем — **обычные арифметические преобразования** (usual arithmetic
conversions), приводящие операнды к общему типу.

Правила (упрощённо):

. Если один операнд имеет тип `long double`, другой приводится к `long double`.
. Иначе если один — `double`, другой — к `double`.
. Иначе если один — `float`, другой — к `float`.
. Иначе применяются продвижения целых.
. Если после продвижения типы совпадают — операция выполняется в этом типе.
. Иначе если оба операнда одного знака — операнд меньшего ранга
  приводится к типу операнда большего ранга.
. Иначе (операнды разных знаков):
  ** если беззнаковый тип имеет ранг не ниже знакового — знаковый
     приводится к беззнаковому;
  ** если знаковый тип может представить все значения беззнакового —
     беззнаковый приводится к знаковому;
  ** иначе оба приводятся к беззнаковому типу, соответствующему
     знаковому.

=== Практические следствия

[source,c]
----
int    i = -1;
unsigned u = 1;

i < u;      /* false: i приводится к unsigned, становится UINT_MAX */
----

Смешение знаковых и беззнаковых типов — классический источник ошибок.
Компиляторы обычно выдают предупреждение при таком сравнении.

[source,c]
----
int    a = 1;
double b = 2.0;

a + b;      /* тип результата — double, значение 3.0 */
----

При смешении целого и вещественного типов целое приводится к вещественному.







Оператор `sizeof` к указателю возвращает размер самого указателя,
а не объекта, на который он ссылается.



== Произвольные целые в C23: `_BitInt(N)`

Стандарт C23 ввёл **genuinely новый** скалярный тип — `_BitInt(N)`,
целое число ровно из N бит.

[source,c]
----
_BitInt(12)          small  = 123wb;
unsigned _BitInt(40) medium = 1000000000000ub;
_BitInt(73)          large  = 0wb;
----

=== Домен значений

* знаковый `_BitInt(N)`: от −2^(N−1)^ до 2^(N−1)^ − 1;
* беззнаковый `unsigned _BitInt(N)`: от 0 до 2^N^ − 1.

Параметр N может быть любым от 1 до значения, публикуемого реализацией
в макросе `BITINT_MAXWIDTH` заголовка `<limits.h>` (стандарт требует
поддержки минимум 1…65535).

=== Множество операций

Те же, что и для обычных целых: арифметика, побитовые операции, сравнения.
Отличия:

* ширина типа точно равна N бит, а не «не менее N бит»;
* суффиксы литералов: `wb` / `WB` для знаковых, `ub` / `UB` для беззнаковых;
* продвижение целых для `_BitInt(N)` при N ≤ ширины `int` выполняется
  до `int`, иначе — до `_BitInt(N)` (беззнаковый — до `unsigned _BitInt(N)`).

=== Область применения

* криптография и хеш-функции, где нужны нестандартные ширины (256, 521 бит);
* сетевые протоколы с полями произвольной ширины;
* работа с аппаратными регистрами;
* ситуации, где требуется ширина, гарантированно не зависящая от платформы.


== Преобразования между скалярными типами

=== Неявные приведения

Неявные приведения происходят:

* при присваивании значения одного скалярного типа переменной другого;
* при передаче аргумента функции (если есть прототип);
* при возврате значения из функции;
* в бинарных операциях — через обычные арифметические преобразования;
* в условии `if`, `while`, `for`, `?:` — приведение к `bool`.

[source,c]
----
int    i = 3.7;       /* 3: отбрасывание дробной части */
double d = 42;        /* 42.0 */
bool   b = -1;        /* true */
----

=== Потеря информации

При приведении вещественного типа к целочисленному:

* дробная часть отбрасывается;
* если значение не помещается в домен целочисленного типа —
  неопределённое поведение (в C23 — определённое, но реализационно-зависимое).

При приведении целого к вещественному:

* значение округляется до ближайшего представимого;
* если значение слишком велико — поведение не определено.

При приведении между целыми不同类型的:

* беззнаковое → знаковое: битовый рисунок сохраняется, интерпретация меняется;
* знаковое → беззнаковое: отрицательные значения приводятся по модулю 2^N^;
* более широкий → более узкий: отбрасываются старшие биты.

=== Явные приведения

Оператор `(T)x` выполняет явное приведение. Он не меняет правил
преобразования, но подавляет предупреждения компилятора и делает
намерения программиста явными.

[source,c]
----
int i = (int)3.7;                 /* явно: 3 */
unsigned u = (unsigned)-1;        /* явно: UINT_MAX */
----

== Резюме

Скалярные типы языка C образуют единое семейство, объединённое тем,
что каждый объект такого типа содержит ровно одно значение.
Однако внутри этого семейства существуют существенные различия:

* **Целочисленные типы** имеют модулярную арифметику для беззнаковых
  и неопределённое поведение при переполнении для знаковых.
  Перед операциями над ними применяется продвижение целых,
  которое часто удивляет начинающих.
* **Вещественные типы** имеют конечный домен со специальными значениями,
  неассоциативную арифметику и значительную часть операций,
  вынесенную в функции `<math.h>`.
* **Булев тип** имеет минимальный домен из двух значений,
  но при арифметических операциях продвигается до `int`.
* **Указатели** имеют домен адресов, а их арифметика зависит
  от типа указуемого объекта.
* **Перечисления** в C не образуют замкнутого множества значений.
* **`_BitInt(N)`** в C23 добавляет целые произвольной ширины.
* **`nullptr`** в C23 даёт отдельный тип для нулевого указателя.

Понимание скалярных типов требует учёта трёх аспектов: домена значений,
множества операций и правил преобразований. Размер в байтах — лишь
следствие этих аспектов, а не их суть.
