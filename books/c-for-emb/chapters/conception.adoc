== Концепции

Прежде чем погрузиться в детали языка C, полезно будет ознакомиться с некоторыми общими концепциями программирования и применить их конкретно к C. Мой опыт проведения собеседований показывает, что не все эмбеддеры хорошо с ними знакомы. При этом знание концепций позволяет лучше понять, почему C именно такой в некоторых аспектах.

В этой главе мы познакомимся с несколькими теоретическими концепциями, которые не имеют непосредственного отношения к деталям программирования на C, а скорее определяют его философию: со специализацией языка, типизацией в языках программирования, способами выполнения кода программы на вычислительной машине, а также основными парадигмами программирования. В заключение определим, какие из этих концепций имеют отношение к C.

=== Языки общего назначения и предметно-ориентированные языки 

Языки программирования существенно отличаются друг от друга, иих можно классифицировать по многим критериям. Одна из фундаментальных классификаций -- это разделение на *языки общего назначения* (General-Purpose Languages, GPL) и *предметно-ориентированные языки* (Domain-Specific Languages, DSL) в зависимости от их назначения.

TIP: Можно привести такую аналогию: GPL — это «мультитул», которым можно сделать (практически) всё; DSL — это специфическая оснастка, специально разработанная и изготовленная для одной конкретной операции.

==== Языки общего назначения

Это языки, созданные для решения максимально широкого круга задач в самых разных областях: от веб-разработки и мобильных приложений до системного программирования и искусственного интеллекта.

===== Ключевые характеристики

* *Тьюринг-полнота:* Могут вычислить любую вычислимую функцию (при наличии достаточного времени и памяти).
* *Универсальность:* На них можно написать практически что угодно без использования других языков: бизнес-приложение (десктоп или веб), сервер, игру, утилиту и т. п.
* *Развитая экосистема:* Стандартные библиотеки, фреймворки, инструменты отладки, сообщества.

===== Примеры

`Python`, `Java`, `C++`, `C#`, `JavaScript`, `Go`, `Rust`, `Swift`.

===== Плюсы и минусы

*Плюсы:*

* *Универсальность:* Изучив один язык, можно работать в разных областях.
* *Масштабируемость:* Подходят для создания сложных программных систем.
* *Инструментарий:* Удобные IDE, профилировщики, отладчики.

*Минусы:*

* *Семантический разрыв:* Средства языка не соответствуют понятиям решаемой задачи. Для решения конкретной задачи приходится писать много кода, который порой непросто понять.
* *Избыточная сложность:* Язык тащит за собой возможности, которые в конкретной задаче не нужны.

==== Предметно-ориентированные языки (Domain-Specific Languages, DSL)

Это языки, созданные для решения задач в *одной конкретной предметной области*. Они жертвуют универсальностью ради максимальной выразительности, краткости и безопасности в своем узком сегменте.

===== Ключевые характеристики

* *Узкая специализация:* Отлично решают одну задачу и обычно бесполезны для всех остальных.
* *Часто не являются Тьюринг-полными:* В них может не быть циклов или условных операторов, что намеренно ограничивает сложность и повышает безопасность.
* *Высокая абстракция:* Операции языка напрямую соответствуют терминам предметной области.

===== Примеры

* `SQL` — для работы с реляционными базами данных.
* `HTML` / `CSS` — для разметки и стилизации веб-страниц.
* *Регулярные выражения (Regex)* — для поиска текстовых шаблонов.
* `Make` / `CMake` / `Gradle` — для автоматизации сборки.
* `GraphQL` — для описания запросов к API.

===== Разновидности DSL

. *Внешние (External DSL):* Имеют свой собственный, уникальный синтаксис и требуют написания собственного парсера или интерпретатора.
* *Примеры:* `SQL`, `HTML`, `Regex`, `LaTeX`.

. *Внутренние (Internal / Embedded DSL):* Не являются самостоятельными языками. Они используют синтаксис языка общего назначения (хостового языка), но применяют специфические библиотеки или паттерны, чтобы код выглядел как предметно-ориентированный.
* *Примеры:* Конфигурация `Gradle` (на Kotlin/Groovy), `SQLAlchemy` в Python, `LINQ` в C#, тестовые фреймворки вроде `pytest`.

===== Плюсы и минусы

*Плюсы:*

* *Краткость и выразительность:* То, что на GPL занимает 50 строк, на DSL может занять 2 строки.
* *Читаемость для непрограммистов:* На DSL может писать специалист в предметной области, не владеющий навыками профессионального программирования (аналитик или даже сам заказчик).
* *Безопасность:* Ограниченный набор операций предотвращает целые классы ошибок, специфических для GPL.

*Минусы:*

* *Узость применения:* Невозможно использовать для других задач.
* *Стоимость создания:* Написание хорошего парсера и инструментов поддержки для внешнего DSL — это дорого.
* *Проблемы с отладкой:* При ошибке стек вызовов может быть непонятен, а инструменты отладки отсутствуют.

==== Современный тренд: Стирание границ

В современной разработке наблюдается интересный симбиоз:

. *DSL внутри GPL:* Разработчики всё чаще создают внутренние DSL на базе языков вроде Kotlin, Scala или Rust, чтобы получить безопасность DSL, но сохранить мощные инструменты компиляции хостового языка.
. *GPL поглощают возможности DSL:* Например, Python имеет встроенную поддержку регулярных выражений (`re`), а многие языки добавляют синтаксический сахар для асинхронности.
. *Infrastructure as Code (IaC):* Такие инструменты, как Terraform (HCL), создают внешние DSL, которые становятся стандартом де-факто для целых индустрий (например, DevOps).

==== Итог

Архитектура современного приложения часто выглядит так: ядро и бизнес-логика написаны на языке общего назначения (`Java`, `Go`, `Rust`), а для конфигурации, запросов, сборки и описания правил используются тщательно подобранные DSL (`SQL`, `YAML`, `Regex`). Это позволяет использовать наиболее подходящий инструмент для каждой конкретной задачи.

=== Парадигмы

Каждый язык программирования поддерживает как минимум одну, а то и несколько *парадигм* одновременно.

**Парадигма программирования** — это философия, которая определяет, как вы структурируете код, как организуете данные и как управляете потоком выполнения программы.

Глобально все парадигмы делятся на два больших типа:
1. **Императивные** (отвечают на вопрос *«Как это нужно делать?»*). Мы подробно пошгово описываем действия, необходимые для получения желаемого реультата.
2. **Декларативные** (отвечают на вопрос *«Что мы хотим получить?»*). Мы описываем желаемый результат, не вдаваясь в детали пошагового выполнения.

Рассмотрим вкратце основные парадигмы.

==== Процедурная парадигма (императивная)

Это подход, основанный на понятии «процедуры» (или функции). Программа представляет собой подробную инструкцию, состоящую из последовательности шагов, которые компьютер должен выполнить от начала до конца для полчения желаемого результата. Процедурную программу часто сравнивают с кулинарным рецептом.

Плюсы: 

* Простота для понимания
* Предсказуемость

Минусы:

* В больших проектах код трудно поддерживать.

Процедурные языки: C, Pascal, BASIC, Fortran.

==== Объектно-ориентированная парадигма (императивная)

Объектно-ориентированная парадигма (ООП) решает многие проблемы процедурного подхода в больших проектах, объединяя данные и операции над ними в единую сущность — **объект**. Программа рассматривается как набор взаимодействующих друг с другом (обычно посредством обмена сообщениями) объектов.

ООП базируется на четырех «китах»:

* **Инкапсуляция:** Скрытие внутреннего состояния объекта и деталей реализации. Доступ к данным осуществляется только через публичные методы (интерфейс).
* **Наследование:** Возможность создать новый объект на основе существующего, унаследовав его данные и поведение (переиспользование кода).
* **Полиморфизм:** Разные объекты, имеющие одинаковый интерфейс, могут реагировать на одно и то же сообщение по-разному.
* **Абстракция:** Выделение главных в данном контексте характеристик объекта и игнорирование второстепенных.


Первоначально ООП разрабатывалась как средство моделирования поведения объектов реального мира, когда каждый объект знает, как реагировать на то или иное сообщение. При этом отправитель сообщения может не вдаваться в детали, как реализован конкретный получатель, если он корректно реализует свой интерфейс.

В качестве аналогии можно привести отправку посылки через почтовое отделение. При этом отправитель имеет дело только с интерфейсом (окошком для приема отправлений), и его не интересует, какими видами транспорта будет доставлена его посылка и на каких промежуточных складах она будет храниться.

Плюсы:

* Хорошо подходит для моделирования сложных систем и реального мира
* Хорошая масштабируемость
* Удобство командной работы (за счет возможности распараллеливания работ над объектами)
* Возможность легкой замены одних объектов другими с тем же интерфейсом, но другой реализацией

Минусы:

* Более сложный код
* Для некоторых задач процедура ("рецепт") подходит лучше, чем сложная модель взаимодействующих объектов.

Языки ООП: Java, C#, C++, Smalltalk, Ruby.

==== Функциональная парадигма (декларативная)

Функциональное программирование (ФП) рассматривает вычисление как применение математических функций. Здесь нет понятий «переменная» в привычном смысле (как ячейка памяти, которую можно перезаписать) и нет «состояния».

Ключевые концепции:

* **Чистые функции:** Функция всегда возвращает одинаковый результат для одинаковых аргументов и не имеет *побочных эффектов* (в частности, не меняет глобальные переменные).
* **Неизменяемость (Immutable):** Данные создаются один раз и не могут быть изменены впоследствии. В случае изменгения создаются новые данные на основе старых.
* **Функции высшего порядка:** Функции могут приниматься как аргументы других функций и возвращаться как результат, то есть не отличаются в этом плане от обычных данных.

В качестве простого примера возьмем формулу `f(x) = x + 2`. Каждый раз, когда `x = 3`, мы будем получать в результате `5` при любых условиях.

Плюсы:

* Код легче тестировать
* Легче реализуются многопоточность и параллельные вычисления, так как нет гонок изменений состояния
* Выше надежность кода

Минусы:

* Крутая кривая обучения для программистов, которые успели привыкнутьк императивным парадигмам
* Плохо подходит для некоторых задач (например, для создания графического интерфейса, работы с вводом-выводом)

Языки: Haskell, Erlang, Lisp, Clojure, Elixir.

==== Логическая парадигма (декларативная)

В логическом программировании программа представляет собой набор **фактов** и **правил** (в виде логических утверждений). Программист не пишет алгоритм решения; вместо этого он описывает предметную область и задает системе **вопрос** (запрос). Система сама находит ответ, используя механизм логического вывода.

Основные области применения:

* Экспертные системы
* Искусственный интеллект
* Парсинг естественных языков
* Доказательство теорем

Языки: Prolog, Datalog.

==== Мультипарадигменные языки

Сегодня «чистые» парадигмы встречаются редко. Большинство популярных языков сегодня являются **мультипарадигменными**. Это значит, что они позволяют программисту выбирать наиболее подходящую парадигму под конкретную задачу.

* **Python:** Хорошо подходит для процедурного стиля(поэтому часто используется как скриптовый язык), при этом поддерживает ООП и имеет элементы ФП (лямбды, `map`, `filter`).
* **JavaScript:** Изначально прототипно-ориентированный (разновидность ООП), но сегодня в нем активно используется ФП (особенно в экосистеме React и Node.js).
* **C++:** Начинался как «C с классами» (процедурный + ООП), но в современных стандартах (C++11/14/17/20) добавлена поддержка функционального стиля.
* **Rust, Scala:** Языки, которые с самого начала проектировались как гибрид ООП и ФП.

==== Итоги

Компетентный программист широкого профиля должен владеть всеми парадигмами. Это позволит ему выбрать наиболее подходящую для данной задачи. Например:

* Хотите смоделировать бизнес-сущности (Пользователь, Заказ, Товар)? -> **ООП**.
* Нужно обработать большой массив данных без побочных эффектов? -> **ФП**.
* Пишете драйвер или код, где важна каждая миллисекунда и контроль над памятью? -> **Процедурный подход**.

Для программиста, специализирующегося на эмбеде, я рекомендую в первую очередь изучить процедурную парадигму. Во многих случаях также уместен объектный подход, но важно соблюдать чувство меры и не создавать объекты ради объектов, а применять их там, где они реально дают более понятный код.

=== Типизация в языках программирования

Одно из важнейших свойств любого языка программирования — то, как он работает с *типами данных*.

Типизацию можно рассматривать по двум независимым осям:

* *Когда* проверяются типы — статическая или динамическая типизация.
* *Насколько строго* проверяются типы — сильная или слабая типизация.

Эти оси *независимы* друг от друга: язык может иметь статическую и сильную типизацию, динамическую слабую и любую другую комбинацию. Рассмотрим каждую ось отдельно.

==== Когда проверяются типы

===== Статическая типизация

При **статической типизации** типы всех переменных и выражений известны *на этапе компиляции* (то есть фактически должны быть заданы в тексте программы к этому моменту). Компилятор анализирует программу ещё до её запуска и проверяет, что все операции применяются к данным подходящих типов. Если проверка не пройдена, программа просто не скомпилируется.

Пример на Java:

[source,java]
----
int x = 10;
x = "hello";  // Ошибка компиляции: нельзя присвоить строку целочисленной переменной
----

Пример на Rust:

[source,rust]
----
let x: i32 = 10;
let y: f64 = x;  // Ошибка компиляции: нельзя неявно преобразовать i32 в f64
----

Преимущества статической типизации:

* Ошибки обнаруживаются до запуска программы, а не в процессе её работы.
* Компилятор может генерировать более эффективный машинный код, зная точные типы данных.
* Инструменты разработки (автодополнение, рефакторинг, навигация по коду) работают гораздо лучше.

Недостатки:

* Приходится писать больше кода для описания типов.
* Меньше гибкости: переменная не может «на лету» изменить свой тип.

Примеры языков со статической типизацией: Java, C, C++, Rust, Go, Haskell.

===== Динамическая типизация

При **динамической типизации** типы проверяются *во время выполнения программы*. Переменная сама по себе не имеет типа — тип имеет *значение*, на которое она ссылается. Одна и та же переменная может сначала хранить число, а потом — строку.

Пример на Python:

[source,python]
----
x = 10        # x ссылается на целое число
x = "hello"   # теперь x ссылается на строку — и это нормально
----

Пример на Ruby:

[source,ruby]
----
x = 10        # x — целое число
x = "hello"   # x — строка, никаких проблем
----

Преимущества динамической типизации:

* Код короче и гибче.
* Быстрое прототипирование: не нужно заранее описывать типы.
* Легко писать обобщённые функции, работающие с данными разных видов.

Недостатки:

* Ошибки типов проявляются только во время выполнения.
* Сложнее обеспечивать корректность больших программ.
* Инструменты анализа кода работают хуже, потому что типы часто неизвестны заранее.

Примеры языков с динамической типизацией: Python, JavaScript, Ruby, PHP, Perl, Lua.

==== Насколько строго проверяются типы

NOTE: Фактически это говорит о том, насколько "охотно" язык выполняет *неявные* преобразования между типами.

===== Сильная (строгая) типизация

При **сильной типизации** язык *не выполняет* неявных преобразований между разными типами. Если операция требует определённого типа, а вы передали другой — будет ошибка.

Пример на Python:

[source,python]
----
result = "5" + 3   # TypeError: нельзя сложить строку и число
----

Пример на Ruby:

[source,ruby]
----
result = "5" + 3   # TypeError: нет неявного преобразования Integer в String
----

Чтобы выполнить операцию, программист должен *явно* преобразовать типы (Пример на Python:):

[source,python]
----
result = int("5") + 3   # 8 — преобразование явное и видно в коде
----

Преимущества:

* Меньше скрытых багов: язык не пытается угадывать ваши намерения.
* Код предсказуем: явно видно, где и какие преобразования происходят.

Недостатки:

* Приходится писать больше явных преобразований.

Примеры языков с сильной типизацией: Python, Ruby, Haskell, Rust, Go, Erlang, Java (с оговорками).

===== Слабая (нестрогая) типизация

При **слабой типизации** язык *сам неявно преобразует* значения между типами, чтобы выполнить операцию. Часто это удобно, но иногда приводит к неожиданным результатам.

Пример на Javascript:

[source,javascript]
----
let result = "5" + 3;   // "53" — число неявно превратилось в строку
let another = "5" - 3;  // 2 — строка неявно превратилась в число
----

Пример на PHP:

[source,php]
----
$result = "5" + 3;      // 8 — строка неявно превратилась в число
----

Пример на C:

[source,c]
----
int x = 10;
double y = x;           // OK: неявное расширение int до double
----

Преимущества:

* Код короче: не нужно писать явные преобразования.
* Удобно в скриптовых задачах.

Недостатки:

* Скрытые баги: язык может «молча» сделать не то, что вы ожидали.
* Сложнее отлаживать: не всегда очевидно, где и какие преобразования произошли.

Примеры языков со слабой типизацией: C, C++, JavaScript, PHP, Perl, Visual Basic.

==== Четыре категории языков

Объединив две оси, получаем четыре категории языков:

[cols="1,2,2",options="header"]
|===
| | Сильная | Слабая

| *Статическая*
| Java, Rust, Go, Haskell
| C, C++, Kotlin (с оговорками)

| *Динамическая*
| Python, Ruby, Erlang
| JavaScript, PHP, Perl
|===

Рассмотрим каждую категорию подробнее.

===== Статическая сильная типизация

Типы известны при компиляции, неявные преобразования запрещены или крайне ограничены.

Пример на Rust:

[source,rust]
----
let x: i32 = 5;
let y: f64 = x;          // Ошибка: нельзя неявно преобразовать i32 в f64
let y: f64 = x as f64;   // OK: явное преобразование
----

Пример на Go:

[source,go]
----
var x int = 5
var y float64 = float64(x) // OK: явное преобразование
var z float64 = x          // Ошибка компиляции
----

Языки этой категории требуют от программиста максимальной дисциплины, но зато дают сильные гарантии корректности. Ошибки, связанные с некорректным использованием типов, практически исключены.

===== Статическая слабая типизация

Типы известны при компиляции, но компилятор охотно выполняет неявные преобразования.

Пример на C:

[source,c]
----
int x = 10;
double y = x;           // OK: неявное расширение int до double
void *p = &x;
int *q = p;             // OK: void* неявно преобразуется в любой указатель
----

Пример на C++:

[source,cpp]
----
void f(std::string s);
f("hello");  // OK: строковый литерал неявно преобразуется в std::string
----

Такие языки дают гибкость, но требуют внимательности: компилятор не всегда предупреждает о преобразованиях, которые могут привести к потере данных или неожиданному поведению.

===== Динамическая сильная типизация

Типы проверяются в рантайме, неявные преобразования запрещены.

Пример на Python:

[source,python]
----
x = "5"
y = 3
z = x + y       # TypeError: нельзя сложить str и int
----

Пример на Ruby:

[source,ruby]
----
x = "5"
y = 3
z = x + y       # TypeError: нет неявного преобразования Integer в String
----

Такие языки сочетают гибкость динамической типизации с предсказуемостью сильной: если что-то пошло не так, вы сразу получите понятную ошибку.

===== Динамическая слабая типизация

Типы проверяются во время выполнения, и язык сам неявно преобразует значения.

Пример на Javascript:

[source,javascript]
----
let x = "5";
let y = 3;
let z = x + y;   // "53" — число превратилось в строку
let w = x - y;   // 2 — строка превратилась в число
----

Пример на PHP:

[source,php]
----
$x = "5 apples";
$y = 3;
$z = $x + $y;   // 8 — строка неявно превратилась в число
----

Это самый «либеральный» режим: язык максимально старается выполнить операцию, даже если программист имел в виду что-то другое.

==== Практические следствия

Выбор языка с той или иной типизацией — это всегда компромисс. Вот несколько общих соображений:

* *Статическая типизация* предпочтительна для больших проектов, где важны надёжность и сопровождаемость. Она помогает находить ошибки на ранних этапах.
* *Динамическая типизация* удобна для прототипов, скриптов и небольших программ, где скорость разработки важнее гарантий.
* *Сильная типизация* снижает количество скрытых багов, потому что язык не «угадывает» ваши намерения.
* *Слабая типизация* сокращает объём явного кода, но требует внимательности: легко получить неожиданный результат.

==== Итоги

* Типизацию удобно рассматривать по двум независимым осям: *когда* проверяются типы (статическая / динамическая) и *насколько строго* (сильная / слабая).
* **Статическая типизация** проверяет типы при компиляции, **динамическая** — во время выполнения.
* **Сильная типизация** запрещает неявные преобразования между несовместимыми типами, **слабая** — выполняет их автоматически.
* Эти оси независимы: язык может быть любой из четырёх комбинаций.
* Граница между сильной и слабой типизацией неформальна и определяется тем, насколько охотно язык выполняет неявные преобразования.
* Выбор типа типизации — это всегда компромисс между гибкостью, безопасностью и объёмом кода.

Знание этих различий помогает лучше понимать философию языка, который вы изучаете.
