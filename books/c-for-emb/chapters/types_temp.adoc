== Массивы

=== Домен: кортеж значений

Тип `T[N]` описывает N последовательно расположенных объектов типа `T`.
С формальной точки зрения его домен представляет собой декартову степень:

    D(T[N]) = D(T) × D(T) × … × D(T)   (N раз)

Многомерный массив в языке C следует рассматривать не как единую «таблицу»,
а как **массив массивов**. Объявление `int m[2][3]` описывает массив из двух
элементов, каждый из которых имеет тип `int[3]`.

=== Операции: особенности массивов

Здесь проявляется существенная особенность языка C.
Массив, несмотря на то что его домен представляет собой кортеж значений,
не является полноценным значением-кортежем:
операции присваивания и сравнения по содержимому для массивов не определены.

[cols="2,2,2",options="header"]
|===
| Операция | Массив `T a[N]` | Указатель `T *p`

| `sizeof` | `N * sizeof(T)` | `sizeof(T *)`
| Взятие адреса | `&a` имеет тип `T (*)[N]` | `&p` имеет тип `T **`
| Присваивание целиком | *не определено* | определено
| `==` | сравниваются адреса после преобразования | сравниваются адреса
| Арифметика `+ n` | через преобразование к `T *` | определена
| Передача в функцию | передаётся указатель | передаётся значение указателя
|===

[source,c]
----
int a[4];
int *p = a;

sizeof a;     /* 4 * sizeof(int) */
sizeof p;     /* sizeof(int *) */

&a;           /* тип int (*)[4] */
&p;           /* тип int ** */

a + 1;        /* адрес a[1] */
&a + 1;       /* адрес, следующий за всем массивом из четырёх int */
----

Последняя строка наглядно демонстрирует, что тип определяет смысл операции:
адрес начала совпадает, однако шаг арифметики различен.

=== Преобразование массива к указателю

В большинстве выражений имя массива автоматически преобразуется
в указатель на его первый элемент. Данное преобразование называется *decay*.

Исключения составляют лишь четыре случая:

* операнд `sizeof`;
* операнд `_Alignof`;
* операнд унарного `&`;
* инициализация символьного массива строковым литералом.

Именно поэтому `sizeof` остаётся единственным способом определить размер
массива после того, как он был преобразован в указатель:

[source,c]
----
void f(int a[10]) {
    /* параметр имеет тип int *, а не int[10] */
    sizeof a;    /* sizeof(int *), а не 40 */
}
----

=== Присваивание массива

Косвенно присваивание массива возможно через содержащую его структуру:

[source,c]
----
typedef int Row[4];
Row x = {1, 2, 3, 4}, y;
/* y = x;                  */ /* ошибка: массивы не присваиваются */

struct Box { int data[4]; };
struct Box b1 = {{1, 2, 3, 4}}, b2;
b2 = b1;                     /* допустимо: присваивается структура */
----

NOTE: В стандарте C99 были введены массивы переменной длины (VLA): `int a[n];`.
Размер домена такого массива становится известен лишь во время выполнения,
и операция `sizeof` вычисляется также во время выполнения.
В стандарте C11 поддержка VLA была сделана необязательной для реализации.


== Структуры

=== Домен: произведение полей

Если массив представляет собой *повторение* одного домена,
то структура — его *произведение*:

[source,c]
----
struct Point {
    int x;
    int y;
};
/* D(struct Point) = D(int) × D(int) */
----

Каждое поле сохраняет собственный тип и собственный домен.
При этом **выравнивающие вставки (padding) не являются частью значения**:
они не несут информации и не обязаны копироваться при присваивании.

=== Операции

Для структурных типов определены:

* доступ к полю через `.` и через `->`;
* **присваивание объекта целиком**;
* передача и возврат из функции по значению;
* агрегатная и именованная инициализация;
* взятие адреса.

Для них *не* определены сравнение `==`, арифметические операции
и неявные приведения к другим структурным типам:

[source,c]
----
struct Point a = { .x = 3, .y = 4 };
struct Point b = a;       /* допустимо: присваивание всего объекта */
b.x += 1;                 /* допустимо */
/* a == b;               */ /* ошибка: операция не определена */
----

Сравнение структур необходимо реализовывать явно.
Попытка сравнить байты через `memcmp` является некорректной,
поскольку выравнивающие вставки могут содержать произвольные значения.

=== Имя типа и тождество типов

В языке C структурные типы обладают *номинативным* тождеством:
две структуры с одинаковыми полями, но различными тегами,
рассматриваются как различные типы.

[source,c]
----
struct A { int x; };
struct B { int x; };

struct A a = {1};
struct B b = a;    /* ошибка: различные типы, несмотря на совпадение домена */
----

Данное обстоятельство существенно уточняет модель «домен + операции»:
совпадение домена само по себе не делает два типа одним типом.

NOTE: Два объявления `typedef` для `int` описывают один и тот же тип.
Две структуры с одинаковым описанием — два различных типа.
Язык C сочетает структурный и номинативный подходы к тождеству типов.

=== Вложение и самоссылка

Структура может содержать другие структуры, массивы и объединения.
Содержать саму себя по значению она не может — размер оказался бы
рекурсивно неопределённым, — однако может содержать указатель на свой тип:

[source,c]
----
struct Node {
    int value;
    struct Node *next;
};
----

=== Гибкий массив в конце

В стандарте C99 было введено специальное поле без указания размера —
гибкий массив-член (flexible array member):

[source,c]
----
struct Vector {
    size_t n;
    double v[];        /* гибкий массив */
};
----

Операция `sizeof(struct Vector)` не включает элементы гибкого массива.
Память под них выделяется отдельно, как правило, следующим образом:

[source,c]
----
struct Vector *v = malloc(sizeof *v + n * sizeof(double));
----

=== Битовые поля

Битовое поле предоставляет способ **сузить домен** поля до N бит:

[source,c]
----
struct Flags {
    unsigned int red   : 3;   /* домен 0…7 */
    unsigned int green : 3;
    unsigned int blue  : 3;
};
----

Операции те же, что и над обычным целым типом, однако над битовым полем
недопустимо взятие адреса, и оно не может быть элементом массива.

=== Объединения: не произведение, а «одно из»

Объединение представляет собой смежный, но иной тип домена.
Вместо декартова произведения все поля накладываются на одну область памяти:
в каждый момент времени объект хранит представление *одного* из них.

[source,c]
----
union Value {
    int    i;
    double d;
};
----

WARNING: Чтение члена объединения, отличного от последнего записанного,
определено в языке C лишь с существенными оговорками и может привести
к получению ловушечного представления. Для гарантированно переносимой
переинтерпретации битового представления следует использовать `memcpy`.


== Функции и void

Два особых случая наглядно иллюстрируют, что тип не всегда описывает
«хранилище значения».

*Тип функции* описывает сигнатуру: тип возвращаемого значения,
типы и количество параметров. Функция не является объектом;
над ней определены операции вызова, взятия адреса и приведения
к указателю на функцию.

*Тип `void`* обладает **пустым доменом значений**.
Объявить объект типа `void` недопустимо, применение `sizeof(void)`
не определено. Однако существует тип `void *` — указатель,
который описывает не тип расположенного в памяти объекта,
а лишь его адрес.

*Неполные типы* (`struct S;`, `extern int a[];`, `void`) —
это типы, домен которых описан не полностью:
о них допустимо рассуждать, однако выделить объект такого типа нельзя.


== Расширения системы типов в стандарте C23

Стандарт C23 — неофициальное название стандарта **ISO/IEC 9899:2024**
(в период разработки — C2x).
Данный стандарт содержит первое существенное расширение системы типов
со времён стандарта C99.

=== `bool`, `true`, `false` — ключевые слова

Домен типа не изменился: по-прежнему ровно два значения.
Изменился **статус типа в языке**.

В стандарте C99 булев тип обозначался как `_Bool`,
а идентификаторы `bool`, `true`, `false` являлись макросами,
определёнными в заголовке `<stdbool.h>`. В стандарте C23 они стали
ключевыми словами.

[source,c]
----
bool ready = true;      /* в C23 заголовочный файл не требуется */
bool failed = false;
----

Идентификатор `_Bool` сохранён как совместимое написание:
речь идёт о том же самом типе.
Заголовок `<stdbool.h>` также сохранён и совместим со стандартом C23.

=== `_BitInt(N)` — целочисленные типы произвольной ширины

Данный тип является **вполне новым** и отсутствовал во всех предыдущих
версиях языка C.

Домен типа `_BitInt(N)` состоит ровно из N бит:

* знаковый вариант: от −2^(N−1)^ до 2^(N−1)^ − 1;
* беззнаковый вариант: от 0 до 2^N^ − 1.

Параметр N не обязан быть степенью двойки:

[source,c]
----
_BitInt(12)          small = 123wb;             /* знаковый, 12 бит */
unsigned _BitInt(40) medium = 1000000000000ub;  /* беззнаковый, 40 бит */
_BitInt(73)          large  = 0wb;              /* не степень двойки */
----

Введены новые суффиксы литералов: `wb` / `WB` для знаковых `_BitInt`
и `ub` / `UB` для беззнаковых.

Стандарт описывает значения N от 1 до 65535; максимальное поддерживаемое
значение реализация публикует в виде макроса `BITINT_MAXWIDTH`
заголовка `<limits.h>`.

Область применения: криптография, сетевые протоколы, работа с аппаратными
регистрами — всюду, где требуется ширина, отсутствующая среди стандартных
целочисленных типов, либо ширина, гарантированно не зависящая от платформы.

=== `nullptr` и `nullptr_t`

До стандарта C23 нулевой указатель приходилось записывать через макрос `NULL`
либо через целочисленную константу `0`. Оба варианта являлись компромиссом.

В стандарте C23 введено ключевое слово `nullptr` с собственным типом `nullptr_t`.

[source,c]
----
int *p = nullptr;

void f(int *);
f(nullptr);            /* однозначно: указатель, а не целое */
----

Домен данного типа состоит из единственного значения — нулевого указателя.
Практическая польза заключается в повышении читаемости и в устранении
зависимости от заголовочного файла, необходимого для `NULL`.

=== Децимальные вещественные типы

Типы `_Decimal32`, `_Decimal64`, `_Decimal128` описывают числа
в **десятичной** плавающей точке, а не в двоичной.

Эти имена не являются совершенно новыми: они присутствовали уже
в стандарте C99, однако в необязательном приложении. В стандарте C23
они перенесены в основной текст. Наличие поддержки в конкретной реализации
по-прежнему следует проверять.

Домен принципиально отличается от домена `float` / `double`:

[source,c]
----
_Decimal64 price = 19.99DD;
_Decimal64 total = price * 3;    /* ровно 59.97 */
----

Суффиксы литералов: `df` / `DF`, `dd` / `DD`, `dl` / `DL`.

Число `19.99` не представимо точно в двоичной плавающей точке,
но представимо точно в децимальной.
Данный пример наглядно демонстрирует, как **смена домена изменяет
набор истинных утверждений** об одних и тех же математических объектах.

=== `typeof`, `typeof_unqual`, `decltype`

Эти конструкции не вводят новых доменов значений,
а предоставляют новые **средства именования и вывода типов**:

[source,c]
----
double x = 1.5;

typeof(x)      y = 2.5;   /* y имеет тип double */
decltype(y)    z = y;     /* тип берётся из объявления y */
----

Оператор `typeof_unqual` выполняет те же действия, что и `typeof`,
однако снимает квалификаторы `const` и `volatile`.

Данные операторы особенно полезны в макросах и обобщённом коде,
где тип выражения заранее неизвестен.

=== Прочие изменения, относящиеся к типам

* Точные целочисленные типы `int8_t`, `int16_t`, `int32_t`, `int64_t`
  и их беззнаковые аналоги, а также семейства `int_leastN_t`
  и `int_fastN_t` стали **обязательными** в заголовке `<stdint.h>`
  для соответствующих ширин, при условии их поддержки реализацией.
  Сами типы существовали и ранее; изменилась гарантия их наличия.
* Атрибуты в синтаксисе `[[...]]` позволяют выражать дополнительные
  требования к использованиям типов и функций.
* Устранён неявный `int`, а объявление `f()` теперь означает
  «функция без параметров», что эквивалентно `f(void)`.


== Итог

Система типов языка C наиболее точно понимается не как перечень
«размеров в байтах», а как соответствие между доменами значений
и множествами операций:

[cols="1,2,3",options="header"]
|===
| Тип | Домен значений | Чего в наборе операций нет

| Скаляр | Одно значение | —
| Массив | Кортеж из N значений | Присваивание и сравнение по содержимому
| Структура | Произведение доменов полей | Сравнение и арифметика целиком
| Объединение | Одно из представлений полей | Одновременная значимость всех полей
| Функция | Не данные, а сигнатура | Присваивание
| `void` | Пустое множество | Любые операции над объектом
|===

Стандарт C23 сохранил данную модель, расширив её:
`bool` получил статус ключевого слова, `_BitInt(N)` ввёл целочисленные типы
произвольной ширины, `nullptr` — отдельный тип нулевого указателя,
децимальные вещественные типы вошли в основной текст стандарта,
а `typeof` / `decltype` предоставили средства вывода типов по выражениям.

Следует помнить, что **тип отвечает не на вопрос «сколько байт»,
а на вопросы «какие значения» и «какие операции над ними допустимы».**
