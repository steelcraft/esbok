== Препроцессор и макрокоманды

Мы уже очень бегло познакомились с ролью препроцессора в главе, посвященной компиляции (TBD). Пришла пора познакомиться с языком макросов детально, поскольку они являются весьма важной частью языка C в целом.

Прежде всего необходимо понять, что препроцессор — это отдельная программа, выполняющаяся *до* передачи исходного текста компилятору. Его задача — выполнить некоторые предварительные преобразования текста программы: подключить заголовочные файлы, раскрыть макроопределения, удалить комментарии и обработать директивы условной компиляции.

IMPORTANT: Препроцессор *не анализирует* синтаксис языка и *не выполняет* проверку типов. Он работает исключительно с текстом, производя в нём механические замены. Это свойство определяет основные опасности макрокоманд.

=== Директивы препроцессора

Все директивы препроцессора начинаются со знака `#`, который должен располагаться в начале строки (допустимы только пробельные символы перед ним). Директива *не требует* точки с запятой в конце и действует до конца строки.

Основные директивы:

[cols="^1,^3", options="header"]
|===
|Директива |Назначение

|`#define`
|Определение макроса

|`#undef`
|Отмена определения макроса

|`#include`
|Включение содержимого файла

|`#ifdef`, `#ifndef`, `#if`, `#elif`, `#else`, `#endif`
|Условная компиляция

|`#error`, `#warning`
|Выдача сообщения на этапе препроцессинга

|`#pragma`
|Передача указаний компилятору
|===

=== Объектные макросы (макросы без аргументов)

*Объектный макрос* — это именованная текстовая последовательность, которая подставляется вместо имени макроса везде, где оно встречается в исходном тексте после точки определения.

Пример:

[source,c]
----
#define MAX_STUDENTS 30
#define PI 3.14159265358979

int group[MAX_STUDENTS];
double area = PI * r * r;
----

После работы препроцессора текст примет вид:

[source,c]
----
int group[30];
double area = 3.14159265358979 * r * r;
----

Объектные макросы традиционно используются для задания именованных констант. Это устраняет так называемые *магические числа* — безымянные числовые литералы, смысл которых неочевиден из контекста.

Макрос может быть определён и без тела — такое определение используется как *флаг* для *директив условной компиляции* (см. ниже):

[source,c]
----
#define DEBUG
----

Отменить определение макроса позволяет директива `#undef`:

[source,c]
----
#undef DEBUG
----

=== Функциональные макросы (макросы с аргументами)

*Функциональный макрос* принимает аргументы и подставляет их в тело определения. Синтаксически такой макрос напоминает вызов функции, однако механизм его работы принципиально иной: происходит не вычисление, а *текстовая подстановка*.

[source,c]
----
#define SQUARE(x) ((x) * (x))
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int y = SQUARE(5);       /* y = ((5) * (5)) */
int m = MAX(a + 1, b);   /* m = ((a + 1) > (b) ? (a + 1) : (b)) */
----

Обратите внимание на скобки вокруг каждого аргумента и вокруг всего тела макроса. Это не излишество, а необходимость, связанная с приоритетом операций. Посмотрим, что будет без таких скобок:

[source,c]
----
#define BAD_SUM(a, b) a + b
int x = BAD_SUM(2, 3) * 4;
----

Раскрытие даст `2 + 3 * 4`, то есть `14`, а не ожидаемые `20`. Правильное определение:

[source,c]
----
#define GOOD_SUM(a, b) ((a) + (b))
----

Его раскрытие даст `((2) + (3)) * 4`, в соответствии с ожидаемым результатом.

=== Операторы `\#` и `##`

В теле функционального макроса могут использоваться два специальных оператора.

==== Оператор `#` ("стрингификация")

Оператор `#`, стоящий перед параметром макроса, превращает фактический аргумент в строковый литерал.

[source,c]
----
#define PRINT_VAR(var, fmt) \
    printf(#var " = %" #fmt "\n", var)

int count = 42;
PRINT_VAR(count, d);
/* Раскрывается в:
   printf("count" " = %" "d" "\n", count);
   что эквивалентно:
   printf("count = %d\n", count);
*/
----

==== Оператор `##` (конкатенация)

Оператор `##` склеивает два лексических элемента в единый идентификатор.

[source,c]
----
#define MAKE_FUNC(name) void func_##name(void)

MAKE_FUNC(init);   /* Раскрывается в: void func_init(void) */
MAKE_FUNC(cleanup); /* Раскрывается в: void func_cleanup(void) */
----

Эти операторы позволяют писать макросы, генерирующие имена идентификаторов и строк, что невозможно реализовать средствами самого языка C.

=== Предопределённые макросы

Компилятор предоставляет ряд макросов, значения которых определяются автоматически. Наиболее употребительные из них:

[cols="^1,^3", options="header"]
|===
|Макрос |Значение

|`\___LINE___`
|Номер текущей строки исходного файла

|`\___FILE___`
|Имя текущего исходного файла (строковый литерал)

|`\___DATE___`
|Дата компиляции в формате "Mmm dd yyyy"

|`\___TIME___`
|Время компиляции в формате "hh:mm:ss"

|`\___STDC___`
|Определён, если компилятор соответствует стандарту \(C)

|`\___STDC_VERSION___`
|Номер версии стандарта C (например, `201112L` для C11)
|===

Эти макросы широко применяются в отладочных сообщениях:

[source,c]
----
#define LOG_ERROR(msg) \
    fprintf(stderr, "Ошибка в %s:%d — %s\n", __FILE__, __LINE__, msg)
----

=== Условная компиляция

Директивы условной компиляции позволяют включать или исключать фрагменты текста программы в зависимости от выполнения некоторых условий. Это необходимо, в частности, для:

* адаптации программы к различным операционным системам и архитектурам;
* включения отладочных фрагментов только в специальных сборках;
* предотвращения повторного включения заголовочных файлов.

==== Директива `#if`

Директива `#if` позволяет включать или исключать блоки кода из компиляции в зависимости от значения константного выражения.

Сначала директива `#if` вычисляет целочисленное константное выражение, составленное из литералов и макросов. 
Если указанное выражение после `#if` вычисляется как ненулевое (то есть истинно), то весь код, который находится между `#if` и соответствующей закрывающей директивой `#endif`, включается в итоговый исходный файл для компилятора. Если же выражение равно нулю (ложно), то этот код полностью игнорируется и в компиляцию не попадает. 

Синтаксис:

[source,c]
----
#if выражение
    // код для компиляции, если выражение истинно
#endif
----

IMPORTANT: Условие должно быть константным выражением (то есть его значение вычисляется на этапе компиляции). 

IMPORTANT: Директива `#if` всегда парная. Для каждой такой директивы должна быть соответствующая закрывающая `#endif`. Если этого не сделать, компилятор выдаст ошибку. 

Внутри блока `#if` можно использовать директивы `#elif` (аналог `else if`), `#else` (альтернативный блок для случая, когда `#if` ложен) и вложенные `#if`. При этом `#else`, если он есть, должен быть последней директивой перед `#endif`. 

Пример использования:

[source,c]
----
#define DEBUG 1

#if DEBUG
    printf("Отладка включена\n");
    // какие-то отладочные функции
#endif

// Нормальная работа
----

В этом примере, если макрос `DEBUG` определён и не равен нулю, в итоговый файл попадут вызов `printf` и `какие-то отладочные функции`; в противном случае они будут исключены из компиляции.

[source,c]
----
#define VERSION 2

#if VERSION >= 2
    void new_feature(void);
#else
    void old_feature(void);
#endif
----

В этом примере производится проверка номера версии. В случае, если номер версии 2 или выше, вызывается функция `new_feature`, в противном случае -- `old_feature`.

==== Директивы `#ifdef` и `#ifndef`

Директива `#ifdef NAME` эквивалентна `#if defined(NAME)`, а `#ifndef NAME` — `#if !defined(NAME)`. Оператор `defined(NAME)` возвращает истинное значение, если макроопределение `#define NAME` было встречено ранее (возможно, без указания значения), и ложное -- в противном случае.

[source,c]
----
#ifdef DEBUG
    printf("Отладочное сообщение\n");
#endif

#ifndef MAX_BUFFER
    #define MAX_BUFFER 1024
#endif
----

Оператор `defined` особенно удобен в сложных условиях:

[source,c]
----
#if defined(OS_LINUX) && !defined(DISABLE_NETWORKING)
    /* код для Linux с поддержкой сети */
#elif defined(OS_WINDOWS)
    /* код для Windows */
#else
    #error "Неподдерживаемая операционная система"
#endif
----

==== Защита от повторного включения

Директивы условной компиляции часто используются в идиоме, которая получила название *include guard*. Она предназначена для решения проблемы повторного включения заголовочного файла.

Эта проблема заключается в следующем. Предположим, в нашем проекте используются заголовочные файлы `a.h` и `b.h`. Каждый из них, в свою очередь, включает вложенный заголовочный файл `c.h` через директиву `#include` (многоуровневое вложение одних заголовочных файлов в другие -- обычная практика.

Допустим, некоторый модуль `d.c` включает и `a.h`, и `b.h`:

[source,c]
----
#include "a.h" <1>
#include "b.h" <2>
----

Сначала препроцессор выполнит первую директиву `#include` (1). Он включит в исходный код модуля `d.c` содержимое заголовочного файла `a.h`, включая вложенный файл `c.h`. Затем будет выполнена вторая директива `#include` (2), в ходе которой в модуль `d.c` будет включено содержимое `b.h`, в том числе (повторно!) и `c.h`.

Когда компилятор дойдет до второй копии `c.h`, он встретит повторные определения типов, переменных и макросов, которые он уже обработал ранее. Это приведет к ошибке компиляции (повторное определение).

Эту проблему нельзя решить, просто удалив директиву `#include "c.h"` из файла `b.h`, поскольку в проекте могут быть и другие модули, которые включают только `b.h`. Теперь ошибка возникнет уже при их компиляции, поскольку необходимые определения из `c.h` теперь недоступны.

На помощь приходит *include guard*:

[source,c]
----
#ifndef MYHEADER_H <1>
#define MYHEADER_H <2>

/* содержимое заголовочного файла */

#endif /* MYHEADER_H */ <3>
----

При первом включении заголовочного файла макрос `MYHEADER_H` не определен, поэтому условие (1) истинно, и выполняется остальной текст макроопределения вплоть до `#endif` (3). Будет опроеделен макрос `MYHEADER_H` (2), а затем обработано содержимое заголовочного файла.

При втором и последующих включениях макрос `MYHEADER_H` уже определен, поэтому условие (2) ложно, и содержимое заголовочного файла игнорируется.

Альтернативой является нестандартная, но широко поддерживаемая директива:

[source,c]
----
#pragma once
----

При ее использовании всегда есть (небольшой) риск, что в данной версии компилятора она не реализована.

== Многострочные макросы

Длинное определение макроса можно разбить на несколько строк, экранируя перевод строки обратным слешем:

[source,c]
----
#define INIT_STRUCT(s) do { \
    (s).x = 0;              \
    (s).y = 0;              \
    (s).flags = 0;          \
} while (0)
----

NOTE: Обратите внимание на конструкцию `do { ... } while (0)`. Она необходима, чтобы макрос, раскрывающийся в несколько операторов, синтаксически вёл себя как *единый оператор*. Это позволяет безопасно использовать его в конструкциях `if`-`else`:

[source,c]
----
if (condition)
    INIT_STRUCT(obj);   /* без do-while здесь возникла бы ошибка */
else
    /* ... */
----

Компилятор распознаёт, что цикл выполняется ровно один раз, и оптимизирует его, не генерируя лишнего машинного кода.

== Достоинства и недостатки макросов

Макрокоманды — мощный, но специфический механизм. Они стали неотъемлемой частью программирования на C и оказываются очень полезными при правильном применении. Однако использовать их нужно с большой осторожностью и всегда отдавать себе отчет, чтьо вы делаете. 

=== Достоинства

. *Отсутствие накладных расходов.* Макрос раскрывается на этапе препроцессинга, поэтому вызов макроса не связан с передачей управления, формированием стекового кадра и возвратом из функции. Это важно в системах с ограниченными ресурсами.

. *Работа с синтаксисом языка.* Макросы способны генерировать идентификаторы (через `##`), преобразовывать их в строки (через `#`) и использовать информацию о месте вызова (`__FILE__`, `__LINE__`). Ни одна языковая конструкция C на это не способна.

. *Условная компиляция.* Препроцессор позволяет включать и исключать фрагменты программы в зависимости от конфигурации сборки.

. *Генерация шаблонного кода.* С помощью макросов можно создавать семейства однотипных функций и структур, что востребовано в системном программировании.

=== Недостатки

. *Отсутствие проверки типов.* Препроцессор не различает типы данных. Ошибка, связанная с несовместимостью аргументов, проявится лишь на этапе компиляции раскрытого текста, что затрудняет локализацию проблемы.

. *Многократное вычисление аргументов.* Если аргумент макроса используется в теле несколько раз, он вычисляется соответствующее число раз. Это порой может привести к неожиданному результату:
+
[source,c]
----
#define SQUARE(X) ((X) * (X))
----
+
Вызов `SQUARE(x++)` приведёт к двойному инкременту переменной `x`, что является источником трудноуловимых ошибок.

. *Сложность отладки.* Отладчик работает с раскрытым текстом, а не с исходным макросом. Сообщения об ошибках указывают на строки раскрытия, а не на строки исходного кода.

. *Нарушение области видимости.* Макрос действует глобально от точки определения до конца файла или до директивы `#undef`. Он не подчиняется правилам блочной области видимости языка C.

== Когда следует применять макросы

Общее правило: *если задачу можно легко решить средствами самого языка C, макрос использовать не следует*.

=== Когда макросы оправданы

* *Условная компиляция* — для адаптации программы к различным платформам и конфигурациям сборки. Альтернатив здесь нет.
* *Защита заголовочных файлов* от повторного включения.
* *Отладочные и логгирующие макросы*, использующие `__FILE__` и `__LINE__`.
* *Генерация однотипного кода* — например, семейство функций для разных типов данных, когда обобщённые средства языка недостаточны.
* *Короткие выражения*, где важна каждая операция (в критичных по производительности участках встраиваемых систем).

=== Когда следует отказаться от макросов

[cols="^1,^1,^1", options="header"]
|===
|Задача |Плохо (макрос) |Хорошо (средства C)

|Именованные целочисленные константы
|`#define SIZE 100`
|`enum { SIZE = 100 };`

|Простые функции
|`#define SQUARE(x) ((x)*(x))`
|`static inline int square(int x) { return x * x; }`

|Полиморфные операции
|`#define MAX(a,b) ...`
|Отдельные функции `max_i`, `max_d` или `_Generic` (C11)

|Строковые константы
|`#define MSG "text"`
|`static const char MSG[] = "text";`
|===

Конструкция `static inline` (стандарт C99) позволяет получить функцию, тело которой встраивается в место вызова, то есть по сути достичь того же отсутствия накладных расходов на вызов функции, что и у макроса, но с полной проверкой типов и корректной работой отладчика.

Оператор `_Generic` (стандарт C11) даёт возможность выбирать реализацию в зависимости от типа аргумента, что позволяет создавать типобезопасные полиморфные конструкции без текстовых подстановок.

[source,c]
----
static inline int    max_i(int a, int b)       { return a > b ? a : b; }
static inline double max_d(double a, double b) { return a > b ? a : b; }

#define MAX(a, b) _Generic((a), \
    int:    max_i,              \
    double: max_d               \
)(a, b)
----

В этом определании макрос используется лишь как тонкая оболочка над типобезопасными функциями, что существенно снижает связанные с макросами риски.

== Резюме

Макрокоманды — неотъемлемая часть языка C. Они предоставляют возможности, недоступные языковым средствам: условную компиляцию, работу с именами идентификаторов, генерацию кода. Однако их простая текстовая природа делает макросы источником труднодиагностируемых ошибок.

Современный стиль программирования на C предполагает *минимизацию* использования макросов. Там, где раньше применялись макросы для констант и простых функций, сегодня следует использовать `enum` и `static inline`. Макросы должны оставаться там, где они действительно незаменимы: в условной компиляции, в отладочных конструкциях и в задачах генерации кода.
